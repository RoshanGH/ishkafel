## 一、为什么是现在：AI 的能力边界画在哪

发展到今天，**AI 在多模态理解上已经完全没有问题**。反复测试下来，它能做到的和
做不到的，界线很清楚：

| AI 今天做得到 | AI 今天做不到 |
|---|---|
| 准确理解你的话术、你要的情感 | **对视频做精细化的裁剪操作** |
| 理解它看到的视频里有什么内容 | 帧级的取舍与手感 |
| 理解画面表达的情感 | |
| 理解口播说的是什么意思 | |

所以「AI 剪视频」在今天这个状态下，出来的东西还是**粗糙**的——不是因为它不懂，
是因为它**手不稳**。

**结论很直接：不要让 AI 去做它做不了的那一段，要把它做得了的那一段彻底接管。**

---

## 二、把内容生产重新拆一遍

一条片子的生产就三段：**脚本 → 拍摄 → 剪辑**。今天再看一遍每一段：

### 脚本

AI 可以写。这一段已经没有争议。

### 拍摄

原始镜头可以人拍，也可以 AI 生成。但**更重要的是另一件事**：

> **AI 可以对拍出来的原始素材做预处理。**

这不是可选项，是**进入生产环节的前提**——素材必须先被理解过（打上标签、写出画面
描述、抽出口播台词），后面那一步才可能交给 Agent。没有这层预处理，Agent 面对的
就是一堆文件名。

### 剪辑

AI 今天没有办法做精细化剪辑，**但它可以把剪辑里最耗时的那个环节彻底取消掉**：

- **找镜头**
- **对齐字幕**
- **镜头替换**

这几件事恰好全都落在「理解」这一侧，不在「精细裁剪」那一侧。

## 三、这个软件的位置：**给 AI Agent 干这一步的工作台**

```
原始镜头                AI 预处理              生产环节                 人
（人拍 / AI 生成）  →  （标签 / 画面描述  →  ishkafel 工作台   →   最后 2~5 分钟
                        / 口播台词）          Agent 在这儿干活        精修
```

因为多模态理解已经到了可用的程度，**找镜头这一步可以完全交给 AI Agent**。
而这个软件，就是给它干这一步的工作台。

它找到镜头之后，还要能干这些——**都在「精细化操作」之外，都是判断题**：

- 这个镜头该放在**哪一个位置**
- 这一镜要**加速还是放慢**
- 一个坑位快速备**多个替换候选**
- 甚至**多个镜头同时替换**

### 这笔时间账

剪辑里那段长达一小时的活，**直接缩减到最后两三分钟到五分钟的人工精修**。
人只做最后那一下——那一下恰好是 AI 做不好的部分。

### 有没有这个软件，区别在哪

这是最要紧的一条。

| | 没有这个软件 | 有这个软件 |
|---|---|---|
| Agent 怎么干活 | **自己写程序**去实现人规定的工作流 | **调用软件里对应的功能** |
| 产出 | 每次现写、每次不一样 | **稳定，而且足够精细** |
| 人要验的东西 | 它写的那份程序对不对 | 它的**判断**对不对 |

让 Agent 每次现写一套 ffmpeg 流程，等于把「精细化操作」又推回给它——
而那正是它做不好的那一侧。软件把这些操作固化成**稳定、帧级正确、有保护的能力**，
Agent 只负责调用与判断。

## 四、两条生产线，各有两种起点

选哪条线，判据只有一个：**原片那个人的声音还要不要。**

| | 有原片 | 没有原片 |
|---|---|---|
| **替换裂变**（工作台）<br>要原声，台词与节奏照搬 | 上传成片 → 分析切分 → 逐镜换素材 | 不用原片，直接从素材拼 |
| **脚本成片**（编导台）<br>不要原声，台词重写、TTS 重念 | 上传参考片 → 提取台词 → 配音配画面 | 直接写台词 → 配音配画面 |

起点（有没有原片）不是模式，只是入口——同一条线进去之后干的是同一件事。

### 两层切分，是这个产品的地基

```
成片
 └─ 台词语义单元（口语叫「分子」，按台词语义切，不按画面切换切）
     └─ 视觉镜头（口语叫「原子」，按画面切换切，严格嵌套在单元内）
```

一句「这个东西能把衣服洗干净」是**一个台词语义单元**，它内部可能过了 3 个
**视觉镜头**：脏衣服 → 正在洗 → 洗干净了。

替换发生在哪一层，决定了它是什么行为：

- **整体替换**（单元层）：画面和声音一起换，时长跟候选走，后面整体后移
- **镜头替换**（镜头层）：只换画面，变速铺满原坑位，时长一帧不变，口播照旧

这两层正是 Agent 下判断的坐标系：它说「U2 的 S2 换成这条」，软件保证换完
**时长一帧不差**、字幕重新烧上去、声音不错位。

## 五、为什么是 Agent，而不是自动化脚本

「自动铺一版」这种整装功能我们做了——**它只配当草片**。一条片子要挑 25~45 个
镜头，每一镜都要看图判断：

- 像不像参考镜？
- 跟前后连不连得上？
- 素材上烧没烧别人的字？
- 露的是不是竞品的产品？
- 够不够铺满这一句话的时长？

**这是判断，不是规则。** 写死规则挑出来的东西，看一眼就知道不能用。

所以要把编导操作台上的**每一个旋钮**都交到 Agent 手上，事实也一样不少地摆给它
（参考图、ASR 台词、画面描述、时长、烧字、品牌），然后**判断权归 Agent，
软件只提供能力和保护**。

推论三条，每条都是踩出来的：

1. **人在界面上能拧的每个旋钮，Agent 都要能拧。** 少一个，它就只能被动接受
   软件给的默认值——那又退回成规则了。
   > 落地成 27 个顶层命令 + 一份内嵌手册（`ishkafel skill --install` 直接装进
   > Claude Code / Codex 的技能目录），外加一条**架构测试**：新加了旋钮却没
   > 写进手册，测试当场红。

2. **软件不替 Agent 做判断，也不背着它自己干活。**

3. **播报只报 Agent 在做什么。** 软件自己跑的活儿不许占那条通道——占了，
   人就分不清是谁在动手。

### 可视化模式不是给 Agent 加日志，它就是产品本身

> 终局是**静默执行**，但通往静默只有一条路：**人得能从头跟着看它是怎么想的。**
>
> 人需要去干涉的时候，你只给他最后的成片去干涉，就已经来不及了。他如果从头
> 跟了你两遍，发现你整个找视频的逻辑都没有问题，那后面就可以写 skills 总结，
> 让 Agent 直接静默执行了。

所以可视化验的是**它的判断逻辑对不对**，不是「它做完了没有」。最值钱的是
判断类播报：

> 「标签命中 5318 条太宽，改用画面描述再搜一轮」

这种话是人肯把花钱的活交给静默模式的**唯一理由**。

## 六、现在它能做到什么（真机数字）

### 一条 75 秒的竖屏口播片

| 事实 | 数字 | 来源 |
|---|---|---|
| 首次可进工作台 | **22.5 秒** | 任务 #3 的 `firstReadyMs` |
| 这一次分析的 AI 花费 | **约 0.27 元** | 任务卡上的实时用量（50 次 LLM + 1 次 ASR） |
| 切出来的结构 | 4 个台词语义单元 / 25 个视觉镜头 | 同一条任务 |
| 另外三条真实任务 | 24.3s / 28.3s 可用，51 和 38 个镜头 | `firstReadyMs` |

这 22 秒里跑完的正是第二节说的**预处理**：提取音频 → 人声/背景分离 →
ASR（句级+字级时间戳）→ 镜头切点检测 → LLM 语义切分 → 两层打标。
分析结果按**源文件内容指纹**缓存，同一条片子再导入直接复用切分。

### 出片这一头

- **矩阵导出**：各位置候选的组合，上限 100 条，一次批量合成
- **「挑差异最大的」**：不是随机抽——每个替换位置的候选按配额摊开
  （5 个候选出 10 条 = 各 2 次），并保证十条之间的搭配互不重样
- **本地合成**：ffmpeg + 硬件编码，素材、声音、字幕都在自己电脑上过，
  云端只负责 AI 那几步
- **交付两种形态**：直接出 mp4/mov 成片；或生成**剪映草稿工程**，
  拖进剪映继续精修——那最后两三分钟就发生在这儿

### 声音这一层

被替换的那一镜，声音是**两层**，各自四档（不播放 / 人声 / 背景声 / 原声）：

- **原片这一镜的声音**：要那句口播、还是要现场音
- **替换素材的声音**：要它的现场感、还是要它说的那句话

两层各选各的，最后按你设的音量**相加**（不是取平均，各层保持自己的音量）。
叠出来真的过载了会**点名是哪一段**，不偷偷帮你压——那等于软件背着人做判断。

换音色（TTS）、配乐（一段可选多首互为备选，导出时轮流用）、字幕
（画面上现画的一层，可直接拖、可按帧改时间）都在同一条时间轴上。

## 七、我们拿什么保证「能用」，而不只是「能跑」

Agent 调用的能力必须**稳定且足够精细**——这一节就是那句话的兑现方式。
判据只有一句：

> **这东西如果是花钱买来的商业软件，用户能忍吗？** 不能忍就是不合格，
> 哪怕功能上「能用」。

落成五条可执行的判据，每一条都有代码和测试守着：

| 判据 | 具体是什么 |
|---|---|
| **不静默降级** | 影响成片的东西出错就失败并点名，不许悄悄少一段、少一句、拿默认值顶上。可降级的只有预览这类「人还在看着」的环节，且必须把降级说出来 |
| **不做一次性的脏活** | 算过一次的东西落地复用，改动了才重算。缓存一律按**内容指纹**判定——按文件名存在就当命中，会静默放出上一个版本的内容 |
| **不留孤儿数据** | 磁盘上每一份数据都要有人读、有人删。产物清单收敛成唯一一份，新增一种产物只改那一处 |
| **状态可见且可操作** | 后台在干活就说清在干什么、到第几步；失败要给原因和重试入口 |
| **自己先验一遍** | UI 改动要真机跑起来截图核对，不允许只报「测试通过」 |

### 工程规模

| | 数字 |
|---|---|
| 产品代码 | **87,138 行** / 409 个文件 |
| 测试代码 | **71,005 行** / 552 个文件 |
| 自动化测试 | **4,196 项**，全绿 |
| **架构守卫** | **51 条** |

架构守卫是这个项目的特色做法：它不测功能，**它扫源码**——比如

- 「导出的六个声音参数，任何一处调用漏传就红」
- 「core 里让人『点某个按钮』的提示，必须同时给出命令行的走法」（命令行那头
  没有按钮可点，Agent 照做会走进死路）
- 「新加的旋钮必须出现在 Agent 手册里」

这类洞不是逻辑写错，是**加东西时忘了改另一处**，只有扫描拦得住。

### 一个真实例子：为什么这套机制值钱

上周有个 bug：替换镜头的声音跑到了片头，还把前面的口播压小了一半。
原因是两处：`adelay` 挪位之后再 `atrim`，会把挪出来的前导静音整段吃掉；
`amix` 默认按路数归一化，叠三层片头就掉 18dB。

**参数看上去全是对的**——原来的测试比对 ffmpeg 参数字符串，全绿。
只有真跑一遍 ffmpeg 把声音合出来、逐秒量电平，这两个错才暴露。

修完还剩一道坎：盘上那些按错规则渲出来的中间产物，指纹没变，重新导出照样
被原样取出来用。所以**规则版本也进了缓存指纹**——老任务直接重新导出就行。

这正是「Agent 调用的能力要稳定」的成本：**它不该在一条坏掉的能力上做判断。**

## 八、技术形态

```
ishkafel.app / ishkafel.exe          ← 一套 Dart 代码编译的原生程序
 ├─ Flutter 自绘 UI（工作台、编导台、双层时间线、预览窗）
 ├─ libmpv（FFI，多轨预览，硬件解码，逐帧）
 ├─ ffmpeg（子进程：切分 / 抽帧 / 变速 / 合成导出，硬件编码）
 └─ HTTP
     ├─ miaoa（素材检索：标签精确筛 / 画面描述语义搜 / 首帧以图搜图）
     └─ 云端 AI（ASR、LLM 语义切分与打标、Vision 画面理解、TTS）
```

几条关键取舍：

- **不是网页套壳**（排除 Electron/Tauri），也不是双原生。视频工具的时间线、
  审片台这类 UI 系统控件给不了，必须自绘
- **本地无 Python、无本地模型、无 CUDA 依赖**。重活在云端和 miaoa，
  本地只做「UI + 编排 + ffmpeg 合成」
- **使用者永远不接触任何云凭据**。内部版编译期注入公司 key，打开即用；
  商业化版走托管中转，客户端零凭据
- **自动更新已上线**：装了 0.1.172 以上的人，下次打开设置就看到更新提示

目前正式包只出 macOS（`.app`，Developer ID 签名）。Windows 是同一套代码，
工程已在仓库里，还没走打包流程。

## 九、现在到哪一步，下一步是什么

**已经在同事手上跑的**（0.1.223）：两条生产线全通、矩阵导出、剪映交付、
两层声音、字幕层、换音色、配乐、自动更新、Agent 全量 CLI + 技能手册。

**下一步的方向**（按价值排）：

1. **从「可视化盯着看」走向「静默执行」**——这是产品设计里写死的终局。
   路径已经定了：人跟着看两遍 → 把判断逻辑写成 skills → Agent 静默出片
2. **商业化形态的凭据与计费**：托管中转服务，客户端零凭据、手机号登录即用
3. **Windows 打包**：代码已经是跨平台的，缺的是打包与签名流程
