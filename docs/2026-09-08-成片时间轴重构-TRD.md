# 成片时间轴重构 · PRD / TRD / 测试方案

> 2026-09-08 立项。起因是同一个病灶连着发出四个症状，一个一个修完还会有第五个。
> 本文先说清病灶，再给目标模型，最后拆成两期可交付的工程方案。

---

## 一、问题（PRD）

### 1.1 用户实际遇到的

产品负责人在真机上连着报了四条，每条看起来都是独立的 bug：

| # | 现象 | 用户原话 |
|---|---|---|
| 1 | 手加的单元拖到最前，播放直接从第二个单元开始 | 「我播放的时候，你竟然是从第二个台词语义单元开始播放」 |
| 2 | 时间线画到 01:47，播放器只到 01:36 | 「然后你看末尾也没对齐」 |
| 3 | 原片里最后一个单元在时间线上整格消失（镜头轨还画着，单元轨是空的） | 附截图圈出 |
| 4 | 那一格点不中、双击播不了 | 「U6 不能正常播放」 |

**四条是同一个病灶。** 逐条打补丁的代价：已经修了三轮，每轮都以为修完了。

### 1.2 用户要的模型

> 「就比如说像剪映，我一个 60 帧的和一个 30 帧的视频，我都拉进去，然后它那个帧是怎么算的……
> 我就想再添加进去一个视频，你不要管它多少帧，反正你最后都换算成帧数……
> 在开头添加，或者在结尾添加，都算是重新计算嘛，都往后排嘛，在轴上往后排。然后都能够正常的去播放。」

拆成可验收的四条：

- **T1** 成片时间轴是第一公民，最小单位是**帧**
- **T2** 素材是多少帧无所谓，进到项目里统一按**项目帧率**换算
- **T3** 在任意位置插入/删除/调序，后面的段全部重排，数字当场跟着变
- **T4** 排完都能正常播放；放不了的段要**点名**，不是静默跳过

### 1.3 非目标

- 不做多轨叠加（画中画、多层视频）——本产品的成片是单轨顺排
- 不做变速曲线、关键帧
- 不改替换裂变/脚本成片的业务规则，只改时间轴的表达方式

## 二、病灶分析

### 2.1 现状：存的是"取自原片哪儿"，要的是"在成片哪儿"

`SemanticUnit.startMs / endMs` 和 `Shot.startMs / endMs` 存的都是**原片时间区间**。
而界面、播放、导出要的是**成片位置**。两者靠 `ComposedTimeline` 上的两个换算连着：

```
toSourceMs(成片时刻)  →  原片时刻      ← 良定义
toComposedMs(原片时刻) →  成片时刻      ← 病态
```

### 2.2 为什么 `toComposedMs` 是病态的

> 给一个原片时刻，问它在成片的哪儿 —— **这个问题本身没有唯一答案。**

三条独立的失效原因：

1. **可能无人覆盖**：手加的单元在原片里不存在，它占的那段时间没有任何原片内容
2. **可能多人覆盖**：同一段原片可以被复用（未来），或被手加单元的"假区间"重叠
3. **开区间边界必然错位**：`endMs` 是开区间，`toComposedMs(unit.endMs)` 匹配到的是**相邻那一段**

第 3 条平时看不出来，因为列表顺序和原片顺序一致时，"下一段的成片起点" 恰好等于
"这一段的成片终点"。**一旦顺序被打乱就完全失效** —— 而拖动调序是一等功能。

实测（`test/features/workbench/timeline/play_range_reordered_test.dart`）：

```dart
// U1 手加，原片占位 [20000,30000)，被拖到列表最前
// U3 取自原片 [10000,20000)，是原片里的最后一段
axis.toComposedMs(units[2].endMs) == 0   // ← 应该是 30000
```

`endMs = 20000` 落进手加单元的占位区间 `[20000,30000)`，于是被算成它的成片起点 `0`。

### 2.3 引信：手加单元被编了一个假的原片位置

```dart
// lib/core/editing/segmentation_edit_ops.dart:434
final start = units.isEmpty ? 0 : units.last.endMs;   // 塞在原片末尾
```

原片只有 96.2s，手加单元却被写成"取自原片 96.233s–106.233s"。
这个数**在原片里不存在**，却和真正最后一个单元的 `endMs`（96233）撞在同一个值上。

模型里已经有 `hasSource: false` 说明"原片里没有它"，但 `startMs/endMs` 仍然被当成原片时间参与所有运算 —— **一个字段说"这不是原片位置"，另外两个字段还在假装它是。**

### 2.4 症状与病灶的对应

| 症状 | 犯在哪 | 已修版本 |
|---|---|---|
| 整格画不出来 | `timeline_painter` 用 `msToPx(unit.endMs)`，矩形左右翻转 | 0.1.194 |
| 点不中 | `timeline_hit_tester` 同上，`x >= start && x < end` 永不成立 | 0.1.195 |
| 双击播不了 | `onPlaySegment` 传毫秒，上层再换算一次，区间翻转成「104s → 0s」 | 0.1.195 |
| 末尾对不齐 | 播放器总长用原片总长；EDL 空洞被压掉 | 0.1.193 / 0.1.195 |

**这四处都是"改调用点"，不是"改病灶"。** 只要 `toComposedMs` 还在，第五处就还会出现。

### 2.5 帧的现状

| 项 | 现状 | 问题 |
|---|---|---|
| 时间单位 | 毫秒（`int`） | 边界不保证落在帧上 |
| 帧长 | `frameMs(fps) = (1000/fps).round()` | 30fps → **33ms**，30 帧累加得 990ms 而不是 1000ms |
| 29.97 与 30 | `round()` 后都是 33ms | 两种帧率**无法区分** |
| 项目帧率 | 没有，只有 `task.videoInfo.fps`（原片的） | 见下方订正 |
| 素材帧率 | `CandidateTrim` 只有 `startMs/durationMs/speed` | 见下方订正 |
| 显示 | `formatTimecode` 用 `fps.round()` 做秒的除数 | 已注明是显示层近似 |

> **订正（2026-09-08 一期落地时核实）**
>
> 上表里"素材帧率完全没参与运算、跨帧率会漂"这条**我写错了**。实际查证：
>
> - `ExportCommands` 已经显式给 `-r target.frameRate`，ffmpeg 把素材归一到
>   项目帧率，输出帧数按 `frameCount(durationMs, atFps: outFps)` 算
> - `MediaSpec.toString()` 含 `@frameRate`，而它在变速切片的缓存 key 里，
>   所以项目帧率变了不会命中旧切片
>
> 也就是说**跨帧率素材本来就是对的**——素材自己的 fps 不需要参与运算，
> 因为归一发生在 ffmpeg 那一步，需要进指纹的是**目标**帧率，而它已经在了。
> 二期不需要为此做任何事。
>
> 真正错的是另外两条，已在一期落地时修掉：
>
> - `frameMs(fps) = round(1000/fps)`：30fps 下 33ms，30 步累加只有 990ms；
>   而且 29.97 和 30 返回同一个值。已删除，±N 帧改成按**帧号**加减
>   （`SegmentationEditOps.msAfterFrames`）。
> - 帧率存成 `double`，`30000/1001` 一转就丢精度。新增 `Rational`，
>   `VideoInfo.fpsExact` 保留原始分数，Agent 侧一并报出。

## 三、目标模型

### 3.1 一句话

**成片时间轴是唯一的主轴，以项目帧率下的"帧"为单位；每一段是一个 clip，
它的位置 = 前面所有 clip 的时长累加；"取自原片哪儿"降级成 clip 身上的一个可选引用。**

### 3.2 数据模型（目标态）

```
Project
  fps: Rational          // 项目帧率，如 30000/1001
  units: [Unit]          // 列表顺序 = 成片顺序

Unit
  durationFrames: int    // 它在成片上占多少帧 ← 唯一的时长真相
  source: SourceRef?     // null = 原片里没有它（手加的）
  shots: [Shot]          // 只在 source != null 时有意义
  ...（台词、标签、声音档位等业务字段不变）

SourceRef
  inFrames: int          // 从素材/原片的第几帧起
  lengthFrames: int      // 取多少帧（按**项目帧率**计）
  assetFps: Rational     // 素材自己的帧率，用于重采样与指纹

Shot
  offsetFrames: int      // 相对所属 Unit 起点的偏移
  durationFrames: int
```

**关键性质：**

- 位置永远是**算出来**的：`start(i) = Σ duration(0..i-1)`，不落库
- 没有任何"原片时刻 → 成片时刻"的映射
- 手加的单元 `source == null`，**不编假位置**
- 反方向（成片位置 → 素材哪一帧）仍然良定义：先按成片位置定位到唯一 clip，再算偏移

### 3.3 帧率换算（对齐剪映）

| 场景 | 处理 |
|---|---|
| 项目帧率怎么定 | 原片的帧率；空白任务取第一条素材的帧率；都没有则 30 |
| 60fps 素材进 30fps 项目 | clip 占 N 项目帧；取素材 `N × (60/30)` 帧重采样成 N 帧 |
| 24fps 素材进 30fps 项目 | 同理，重采样补帧 |
| 帧率进指纹 | `SpeedFitter` / 导出的缓存 key 必须含 `assetFps` 与 `projectFps`，否则改了帧率却命中旧切片 |
| 非整数帧率 | 用有理数（`30000/1001`）而不是 `double`，避免 29.97 与 30 被 `round()` 混为一谈 |

### 3.4 时长与显示

- 存的是帧，显示是 `分:秒.帧`（已有 `formatTimecode`，改成吃帧号）
- 毫秒只在与 ffmpeg / mpv 交界处出现，且由帧号统一换算，不反向存回

## 四、技术方案（TRD）

分两期。**第一期不动存档格式**，把病灶切掉；**第二期换模型**。
两期之间可以停留任意久，第一期本身就是完整可交付的。

### 一期 · 切掉病态方向（不改存档）

#### 目标
删掉 `原片时刻 → 成片时刻` 这条路，让"这一段在成片哪儿"只能按**列表下标**问。

#### 改动清单

| 序 | 文件 | 改什么 |
|---|---|---|
| 1 | `core/export/composed_timeline.dart` | 删 `toComposedMs`；`toSourceMs` 保留（良定义）；补 `endOf(i)`、已有 `composedShotStart/End` |
| 2 | `features/workbench/timeline/timeline_geometry.dart` | 删 `msToPx` / `pxToMs`，只留 `composedMsToPx` / `pxToComposedMs`；需要原片时刻的调用方改走 `axis.toSourceMs` |
| 3 | `timeline_painter.dart` | 已改（`_unitPx` / `_shotPx`），删掉两个助手里的 `msToPx` 兜底 |
| 4 | `timeline_hit_tester.dart` | 同上 |
| 5 | `workbench_body.dart` | 删 `_composed(sourceMs)`；`onUnitTap` 改用 `axis.startOf(i)`；`_playRange` 已按下标 |
| 6 | `core/playback/track_plan.dart` | `toComposedMs` 只在"记住我停在哪儿"处使用，改成按段下标记忆；或删除并改用成片位置直存 |
| 7 | `core/playback/multitrack_playback.dart` | 跟随轨对齐改走成片位置，不再原片↔成片来回换 |
| 8 | `features/workbench/preview_tracks.dart` | `toSourceMs` 保留；确认无 `toComposedMs` 残留 |
| 9 | `bgm_track.dart` | `BgmSpan` 的 `startMs/endMs` 明确为**成片**毫秒，由 `axis.rangeOfUnits` 产出 |

#### 一期完成判据

- `grep -rn "toComposedMs" lib/` 只剩 0 处
- `TimelineGeometry` 上不存在接受原片毫秒的方法
- 架构守卫 `test/architecture/no_source_ms_to_px_test.dart` 收紧到 **0 处允许**

#### 一期不解决什么（要写进 CHANGELOG 明说）

- 存档单位仍然是毫秒，不是帧
- 手加单元仍然带着假的原片区间（只是没人再拿它去算位置了）

一期实际**多做**了两件（本来排在二期，落地时发现代价很小）：

- `±N 帧`改成按帧号加减，删掉 `frameMs`（`msAfterFrames`）
- 新增 `Rational`，`VideoInfo.fpsExact` 保留原始分数，29.97 与 30 分得开

### 二期 · 换成"帧 + clip"模型（动存档）

> **2026-09-08 复盘后的取舍：暂不做，且理由不是"来不及"。**
>
> 一期落地后重新核了一遍，二期原本要解决的三件事里有两件已经不成立：
>
> | 二期原计划 | 复核结论 |
> |---|---|
> | 跨帧率素材按帧重采样 | **本来就是对的**：ffmpeg `-r target.frameRate` 已在归一，目标帧率也在缓存指纹里。见二、2.5 的订正 |
> | 帧算术精确、29.97 与 30 分得开 | **一期已做**：`msAfterFrames` + `Rational` |
> | 存档单位从毫秒改成帧 | 仍未做 —— 见下 |
>
> 剩下的只有"存档单位改成帧"。它的收益是**架构纯度**，而不是任何一条可观察
> 的行为：边界已经帧吸附、±1 帧已经精确、显示已经是 `分:秒.帧`、跨帧率已经
> 归一。代价则是改 361 处引用 / 65 个源文件 / 164 个测试文件，并动盘上的存档
> 格式，其中导出画质、剪映工程这些最要命的部分**没有自动化手段能验**。
>
> 所以这一节保留为设计记录，等出现一个真正需要它的场景（多轨、变速曲线、
> 或跨项目复用素材）再启动。届时"旧任务不用管、只保证新任务是新模型"这条
> 产品决定可以让迁移大幅简化。

#### 2.1 新增

```
lib/core/time/rational.dart        有理数帧率（30000/1001），加减乘除与比较
lib/core/time/frames.dart          帧 ↔ 毫秒、跨帧率重采样、整帧吸附
lib/core/models/source_ref.dart    SourceRef { inFrames, lengthFrames, assetFps }
```

#### 2.2 模型改造

`SemanticUnit`：
- 新增 `durationFrames`、`source: SourceRef?`
- `startMs/endMs` 降级为**读存档时的迁移入口**，不再参与任何运算
- `hasSource` 由 `source != null` 推导，字段本身移除

`Shot`：
- 新增 `offsetFrames`、`durationFrames`
- `startMs/endMs` 同上

#### 2.3 迁移（读存档时一次性，写回新格式）

```
projectFps = videoInfo.fps ?? 30
对每个 unit（按列表顺序）:
    durationFrames = msToFrames(endMs - startMs, projectFps)
    source = hasSource
        ? SourceRef(inFrames: msToFrames(startMs), lengthFrames: durationFrames,
                    assetFps: projectFps)
        : null                       // ← 假的原片位置就此丢弃
    对每个 shot:
        offsetFrames   = msToFrames(shot.startMs - unit.startMs)
        durationFrames = msToFrames(shot.endMs - shot.startMs)
```

**迁移要点：**
- 写回前先把原文件复制成 `<id>.pre-frames.json` 备份（一次性，迁移成功后保留 30 天）
- 迁移失败**不吞**：任务标成"打不开"并说明原因，不能让它半迁半不迁地存回去
- 版本号写进任务 JSON（`schema: 2`），读到 `schema >= 2` 直接走新路径

#### 2.4 素材帧率

- `PickedMaterial` 增加 `fps`（探测时一并记下）
- `CandidateTrim` 改成帧：`inFrames / lengthFrames`，并带 `assetFps`
- `SpeedFitter` / 导出的缓存 key 加入 `assetFps` 与 `projectFps`
- 跨帧率时 ffmpeg 侧显式给 `-r <projectFps>`，不靠默认行为

#### 2.5 边界编辑

- 拆分/微调一律在帧域做：`±1 帧` 就是 `±1`，不再 `round(1000/fps)`
- 吸附：拖拽落点先转帧号再取整
- 删掉 `frameMs(fps)` 这个 30fps 与 29.97fps 不分的函数

## 五、测试方案

### 5.1 分层

| 层 | 目标 | 形态 |
|---|---|---|
| L1 单元 | 换算与重排的数学正确 | 纯函数测试 |
| L2 契约 | 病态路径不复活 | 架构守卫（源码级），**每条都要反向验** |
| L3 组件 | 绘制/命中/播放三处口径一致 | 像素级 + 命中测试 |
| L4 端到端 | 真机可用 | 任务副本上手动跑清单 |

### 5.2 L1 · 必须覆盖的用例

**重排**
- 空列表、单元素
- 在**开头**插入、在**中间**插入、在**末尾**插入
- 删除首/中/末
- 调序：相邻交换、跨多格拖动、拖到首、拖到尾
- 每次操作后断言：`start(i) == Σ duration(0..i-1)`、`total == Σ duration`

**跨帧率**
- 60fps 素材 → 30fps 项目：占 N 帧就要取素材 2N 帧
- 24fps → 30fps
- 29.97 与 30 **必须产生不同结果**（现状分不开，这是回归点）
- 帧数换算往返：`framesToMs → msToFrames` 恒等

**手加单元**
- `source == null` 的单元不参与任何"原片位置"运算
- 它的时长按整帧对齐
- 它排在首/中/尾时，前后段的位置都对

### 5.3 L2 · 架构守卫（源码级，反向验证是硬要求）

| 守卫 | 断言 | 反向验证方式 |
|---|---|---|
| 病态方向已删除 | `lib/` 里不出现 `toComposedMs` | 加回一处调用 → 必须挂 |
| 几何层不吃原片毫秒 | `TimelineGeometry` 无 `msToPx` | 加回方法 → 必须挂 |
| 位置只能按下标问 | 绘制/命中里 `msToPx(unit|shot…)` 计数为 **0** | 改回旧写法 → 必须挂 |
| 双击传下标 | `onPlaySegment` 签名是 `(int, int?)` | 改回毫秒 → 必须挂 |
| 时间码只有一处实现 | 全仓只有一个 `formatTimecode` | 复制一份 → 必须挂 |
| 产物已登记 | 新目录都在 `TaskArtifacts` | 加一个未登记目录 → 必须挂 |

> **教训**：本轮第一版守卫用"在不在助手函数内部"做判断，把接线改回旧写法它照样绿。
> 守卫写完必须**故意打断一次**，看它是不是真的会挂。

### 5.4 L3 · 三处口径一致

同一份数据分别问三处，结果必须一致：

```
绘制：_unitPx(i)            → 像素区间
命中：hitTest(该区间中点)    → UnitBlockHit(i)
播放：_playRange(i, null)    → 成片区间，且 end > start
```

用例矩阵（每条都跑上面三问）：

| # | 场景 |
|---|---|
| 1 | 顺序正常，无整体替换 |
| 2 | 手加单元在**开头** |
| 3 | 手加单元在**中间** |
| 4 | 手加单元在**末尾** |
| 5 | 两个真实单元对调（不含手加） |
| 6 | 整体替换改变时长 |
| 7 | 整体替换 + 调序 + 手加，三者叠加 |
| 8 | 最后一个单元的**最后一镜**（`endMs` 边界，本轮病灶所在） |

### 5.5 L4 · 真机验收清单（在任务副本上跑，不动真实数据）

1. 加一个单元 → 拖到最前 → 左栏、时间线、属性栏三处时间一致
2. 按播放 → 在没素材的那段**停下来点名**；再按一次 → 跳过继续
3. 双击每一个单元（含首、末）→ 播的是它自己那一段，播完停在它的终点
4. 双击最后一个单元的最后一镜 → 同上
5. 末尾对齐：播放器总长 == 时间线右端 == 底部"时长"
6. 拖一个 60fps 素材进来 → 能播，且时长与坑位一致（二期）
7. 删掉刚加的单元 → 所有数字当场回退，无残留
8. 关掉重开 → 上述全部保持（存档往返）

## 六、风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| 二期迁移写坏存档 | 任务打不开 | 迁移前整份备份；失败不半写；`schema` 版本号双向可判 |
| 361 处引用改漏 | 编译不过（好）或口径不一致（坏） | 先把 `startMs/endMs` 标 `@Deprecated`，靠编译器逐个逼出来 |
| 缓存 key 变化导致全量重渲 | 首次打开变慢 | 可接受，一次性；且切片本来就该按新帧率重渲 |
| 跨帧率重采样画质/流畅度 | 观感 | 二期先在副本上做 A/B，用真片确认一次 |
| 一期与二期之间长期停留 | 两套概念并存 | 一期完成判据里明确"病态方向 0 处"，不留中间态 |

**回滚**：一期不动存档，`git revert` 即可。二期发版前保留 `pre-frames` 备份，
回滚脚本按 `schema` 版本号把新格式转回旧格式（迁移函数写成双向的）。
