#### `topLit()` 上沿高光渐变（`app_colors.dart:90-95`）

```dart
LinearGradient topLit(Color base) => LinearGradient(
      begin: Alignment.topCenter,
      end: Alignment.bottomCenter,
      colors: [Color.alphaBlend(AppColors.topHighlight, base), base],
      stops: const [0, 0.06],   // 高光只占顶部 6%
    );
```

> **这是全 app「材质感」的来源**，几乎每个浮起面板都要有。
> 之所以用渐变而非 `Border(top:)`，是因为 Flutter 不允许「有圆角时四边异色」。

## 4.3 关键组件的精确尺寸

### 4.3.1 窗口尺寸 ⚠️ **Windows 侧目前不对齐**

`macos/Runner/MainFlutterWindow.swift`：
**默认 `1440 × 900`**（:11），**最小 `1100 × 880`**（:21）。

原注释逐字抄录（**这段推导是资产，不要在 Windows 侧重来一遍**）：

```swift
  /// 默认窗口尺寸。
  ///
  /// 审片台是三栏（单元列表 320 + 播放器 + 检查器 300）加双层时间线，
  /// xib 里默认的 800×600 下：横向播放器只剩两百多像素、竖屏画面几乎看不清；
  /// 纵向时间线区只有约 145px，而四条轨（含标题条）需要 248px，音频波形轨
  /// 整条落在可视区外。这里给一个真正能工作的初始尺寸。
  private static let defaultSize = NSSize(width: 1440, height: 900)      // :5-11

  /// 最小窗口尺寸。
  ///
  /// 高度由时间线反推：六条轨（含标题条）330px + 工具条 40px = 370px。
  /// 时间线区按内容要多少给多少，上限是 body 的 55%（见 workbench_body.dart），
  /// 于是 body 至少要 370 ÷ 0.55 ≈ 673；body = 高度 − 顶栏 52 − 底栏 60 −
  /// 分隔线 1，所以窗口至少 786。取 880 留一档余量——那样六条轨在**任何**
  /// 允许的窗口尺寸下都完整可见，不用滚。
  /// 见 test/features/workbench/timeline/timeline_tracks_layout_test.dart。
  private static let minSize = NSSize(width: 1100, height: 880)          // :13-21
```

> ### ⚠️ Windows 现状
> - `windows/runner/main.cpp:28-29` 仍是模板值 `origin(10, 10)` /
>   `size(1280, 720)`
> - **完全没有设置最小尺寸**
>
> **720 高在此布局下会失败**：body = 720 − 52 − 60 − 1 = 607，
> 55% 上限 = 333.85 **< 370**，第六条轨（音频波形）会看不全
> ——正是 macOS 侧注释里描述的那个 bug。
>
> **要做**：
> 1. `main.cpp` 改成 `Size(1440, 900)` 并居中（现在是 `origin(10,10)`）
> 2. 在 `Win32Window` 的 `WM_GETMINMAXINFO` 里加 `1100 × 880` 下限
> 3. ⚠️ **Win32 的 `Size` 是物理像素**，需按 DPI 缩放换算

### 4.3.3 审片台三栏布局

宽度由 `workbenchPanelWidths()` 计算

**输入常量**：

| 常量 | 值 | 说明 | 行 |

| `_playerChromeHeight` | **96** | 播放器控制条占高 | :21 |

| 右栏上限 | `clamp(总宽 × 0.28, 480, 620)` | | :28-29 |

**算法**（:68-87）：给定 `stageHeight` 后先算
`videoHeight = stageHeight − 96`，`playerWidth = max(280, videoHeight × 9/16)`；
余量按 tab 分配——
- **候选面板激活**：余量若大于右栏基准则全给右栏（**不受 620 上限**）
- **检查器模式**：余量先喂右栏到上限 620，再喂左栏到上限 760

> **这个「打开候选面板时三栏重新分配」的行为在截图上看得很清楚**：

> vs `ui-baseline/13-审片台-替换素材面板.png`（左栏收到 ~318）。

**`pubspec.yaml` 没有 `fonts:` 段** —— **应用不打包任何字体，全部依赖系统字体。**

### 4.5.2 问题一：默认字体的实际解析结果不同

`buildAppTheme()` **没有设 `fontFamily`**，只设了 `fontFamilyFallback`。
Flutter 的行为是：先用 `fontFamily`（null → 平台默认），再按 fallback 顺序找缺字。

| 平台 | 默认字体 | 中文兜底 |
|---|---|---|
| macOS | `.AppleSystemUIFont`（**SF Pro**） | **PingFang SC** |
| Windows | **Segoe UI** | **Microsoft YaHei** |

**后果**：SF Pro 与 Segoe UI 的 x-height、字宽、默认 line-height 都不同；
PingFang SC 与 Microsoft YaHei 的中文字面差异更明显（YaHei 更宽更重）。

> **在 10–13px 这个区间，两者的行盒高度差可达 1–2px，会逐级放大到面板高度。**
>
> 而这个 app 的字号阶梯正好整个落在 10–13px（见 4.1.2）——
> `app_typography.dart:8-9` 的注释明写理由是
> 「macOS 系统字体（SF Pro / PingFang SC）在 10–13px 区间仍然清晰」。
> **Windows 的 Segoe UI / 微软雅黑在 10–12px 下发虚**（尤其无 ClearType 时），
> 这是明显的观感回归风险。

### 4.5.3 问题二：`Menlo` 只有 macOS 有

6 处，全在设置页和标签溯源区，用于展示**路径 / JSON / ID** 等等宽文本。
Windows 上 `Menlo` 会**静默 fallback 到默认比例字体，等宽排版直接垮掉**
（路径、JSON 会对不齐）。

### 4.5.4 建议

> **要真正做到像素级对齐，只有一条路：把字体打进 assets，两个平台都用同一份。**

1. **中文 + 西文**：打包一份开源字体
   （思源黑体 Source Han Sans / Noto Sans SC / HarmonyOS Sans / MiSans）。
   **PingFang SC 有版权，不能分发。**
2. **等宽**：打包 `JetBrains Mono` / `Source Code Pro` / 思源等宽，
   抽一个 `AppFont.mono` token 替掉那 6 处 `Menlo`。
3. 退而求其次（不打包字体）：Windows 上把 `PingFang SC` 换成
   **`Microsoft YaHei UI`**（比 `Microsoft YaHei` 更接近 PingFang 的紧凑感），
   等宽换 `Consolas` / `Cascadia Mono`。**但这样做不到像素级。**
4. **无论走哪条**：对高度敏感的定高容器（顶栏 52 / 底栏 60 / 行高 72 /
   tab 34 / 轨道标题 14）显式 `SizedBox` 锁高。
   **现有代码大部分已经这么做了** ✅
5. 未锁高的（输入框、按钮）需要实测微调。

> ⚠️ **注意**：`subtitle_rasterizer.dart:203` 里成片字幕用的是
> **`PingFangSC-Semibold`**。字幕渲染换实现时，字体也要一起统一——
> 否则成片字幕两边字形不同，而**那才是真正要逐像素一致的东西**。

## 4.7 暗色 / 亮色

> ### 只有暗色模式，没有亮色模式。这是硬编码的，不是用户偏好。

| 证据 | 出处 |
|---|---|
| `MaterialApp` 只传 `theme:`，**没有 `darkTheme:`，没有 `themeMode:`** | `app/app.dart:12` |
| `ThemeData(brightness: Brightness.dark)` 写死 | `app_theme.dart:6` |
| `ColorScheme.dark(...)` 写死 | `app_theme.dart:7` |
| 全仓 `grep "themeMode\|ThemeMode\|Brightness\."` **仅 1 处命中** | — |
| 测试断言 `theme.brightness == Brightness.dark` | `app_theme_test.dart:27` |
| 设计文档明写「最亮的一层也该是深色，**这是个盯着看一天的工具**」 | `surface_layers_test.dart:53-54` |

**Windows 端不需要做亮色模式，且必须禁止跟随系统主题。**
Flutter 在 Windows 上不会自动跟随系统暗色（`theme:` 就是唯一主题），
这一点天然对齐 ✅

> ⚠️ **但要确保系统标题栏也是暗色**：
> `DwmSetWindowAttribute(hwnd, DWMWA_USE_IMMERSIVE_DARK_MODE, &TRUE, ...)`，
> 否则会出现**暗色内容 + 亮色系统标题栏**的割裂。
> macOS 侧因为 `MainFlutterWindow` 继承系统暗色不存在这个问题。

## 4.8 Windows 对齐检查清单（按优先级）

| # | 项 | Windows 现状 | 要做什么 |
|---|---|---|---|
| 1 | **窗口默认尺寸** | `windows/runner/main.cpp:29` 是 `Size(1280, 720)` | 改为 **1440 × 900**（Win32 是物理像素，按 DPI 换算），并**居中**（现在是 `origin(10,10)`） |
| 2 | **窗口最小尺寸** | **完全没设** | `Win32Window` 加 `WM_GETMINMAXINFO`，下限 **1100 × 880** |
| 3 | **中文字体** | 落到 `Microsoft YaHei` | **打包开源中文字体，两边同一份**（否则做不到像素级） |
| 4 | **等宽字体** | `Menlo` 6 处会 fallback 成比例字体 | 打包等宽字体或换 `Consolas`，抽 `AppFont.mono` token |
| 5 | **成片字幕字体** | `PingFangSC-Semibold` 不存在 | 和 3 一起解决——**这条关系到成片逐像素一致** |
| 6 | **系统标题栏暗色** | 默认亮色 | `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)` |
| 7 | **输入框/按钮高度** | 依赖字体 metrics，会漂 | 实测 macOS 值后显式锁高 |
| 8 | **滚动条** | Windows 默认占位，会挤掉布局宽度 | `ScrollbarTheme` 统一成覆盖式 |
| 9 | **DPI 分数缩放** | 1.25 / 1.75 等 | 验证缩略图解码、1px 细边框有无模糊 |
| 10 | 三条守卫测试的路径 | `Directory('lib')` + `contains('app/theme')` 硬编码斜杠 | 改用 `p.join` / `Platform.pathSeparator` |
| 11 | 页面转场 | 已覆盖全平台 | ✅ 无需处理 |
| 12 | 主题模式 | 无 darkTheme/themeMode | ✅ 天然对齐 |
