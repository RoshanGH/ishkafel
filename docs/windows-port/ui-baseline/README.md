# UI 截图基准

> **28 张 macOS 真机截图**，像素级对齐的视觉依据。
>
> - 版本：**0.1.226**（Release 构建，不是调试构建）
> - 窗口：**1440 × 900**（`MainFlutterWindow.swift` 里的默认尺寸）
> - 截图即窗口，**坐标 1:1**，图上量到的 (x, y) 就是窗口内坐标
> - 采集方式：`scripts/shot_app.sh`（`CGWindowListCopyWindowInfo` 定位窗口 +
>   `screencapture -x -o -l <winid>`，不含窗口阴影）
>
> **这些是基准，不是参考。** Windows 侧做完对应页面后，
> 在同样 1440×900 下截同一个页面，两张图应当布局完全重合、配色完全一致、
> 文案完全一致（除 `../02-功能对齐清单.md` 附二列出的几项），
> **差异只落在文字抗锯齿层面**。
>
> 精确数值见 `../04-UI视觉规范.md`——那里的数字有测试钉着，比截图更硬。

---

## 怎么用这些图

1. **先整体翻一遍**（十分钟），建立对这个软件的直觉
2. 做某个页面时，把对应那张放在旁边
3. 做完截图叠一下，**差异逐条问：这是「系统原生」还是「产品本身」？**
   （判据见 `../06-移植建议.md` 6.2）

> ⚠️ `docs/design/` 下还有四组**设计稿**（HTML 原型渲染图）。
> **对齐以本目录的真机截图为准**，设计稿只用来理解意图。

## 采集环境说明

- 截图来自**产品负责人的真实数据**（滴露相关的四条测试任务）
- 任务 #5「Windows移植-截图用-可删」是为了截编导台**临时建的脚本成片任务**
  （脚本成片建出来不跑分析、不花 AI 额度），5 行台词由 CLI
  `ishkafel script apply lines` 写入。**这条任务可以随时删掉。**
- 采集时**只做导航操作**（进页面、切 tab、开面板），
  没有点任何会写入数据的按钮
