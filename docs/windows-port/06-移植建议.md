## 6.2 「所有东西都一样」与「必须是系统原生的 APP」怎么并存

这两条听起来矛盾，其实不矛盾——**它们说的是两件不同的东西。**

### 划线的判据只有一句

> **这个东西是「Windows 用户对操作系统的预期」，还是「ishkafel 这个产品的样子」？**
>
> - 前者 → **入乡随俗**，跟 Windows 走
> - 后者 → **逐像素对齐**，跟 macOS 版走

一个 Windows 用户打开这个软件，他的预期是：窗口按钮在右上角、Ctrl 是主修饰键、
右键菜单是系统样式、文件对话框是 Windows 的、「在资源管理器中显示」而不是
「在访达中显示」。**这些跟 ishkafel 是什么软件毫无关系**，改成 macOS 的样子
只会让他觉得这是个粗糙的移植。

而三栏怎么分、时间线占多高、六条轨各多厚、间距是 8 还是 12、警告用哪个橙色、
「还导不了」那句话怎么说——**这些就是 ishkafel**。它们跟操作系统没关系，
两边不一样就是两个软件了。

### 具体划线

**`允许不同`（= 系统原生的那部分）—— 穷举，不在这张表上的一律要一样：**

窗口标题栏与按钮、系统菜单栏、主修饰键（⌘→Ctrl）、多选点击修饰键、
「在访达中显示」→「在资源管理器中显示」、文案里的「终端」→「PowerShell」、
路径显示方式（不用 `~`）、成片默认落点（Movies→Videos）、等宽字体、
滚动条样式、滚轮缩放手感、安装与分发形态、提权方式、隐私授权。

完整表格见 `02-功能对齐清单.md` **附二**。

**其余一切 `必须一样`**：布局、间距、配色、字号、圆角、阴影、动效时长、
信息架构、交互规则、文案措辞、时间线的每一个像素、模态与非模态的选择、
拦截规则、错误提示的内容。

### 有一条例外，它比「一样」更硬

> **成片必须逐像素一致。**

导出的 mp4、烧上去的字幕、生成的剪映草稿——这些是**交付物**，不是界面。
同一条任务、同一套方案，在 macOS 和 Windows 上导出，应当**逐帧一致、
字幕逐像素一致**。两台机器出来不一样就是事故。

这条约束直接推出两个技术要求：
1. **字幕渲染必须两边同一个实现、同一份字体文件**（见 6.3）
2. **ffmpeg 版本与编码参数两边要锁死**（见 6.5）

### 关于「界面像素级对齐」的现实定义

跨 OS 的**文字抗锯齿**做不到绝对逐像素（CoreText vs DirectWrite，
子像素渲染策略不同）。所以现实的定义是：

> **同字体、同布局、同间距、同配色；两张截图叠起来，
> 差异只落在文字抗锯齿这一层。**

要做到这一点，**必须把字体打进 assets，两个平台用同一份**——
否则 SF Pro/PingFang 与 Segoe UI/雅黑的字宽差异会让布局逐级漂移
（详见 `04-UI视觉规范.md` 第 4.5 节）。这一步不做，其余对齐都是白费。

## 6.3 字幕渲染：唯一必须换实现的地方

### 现状

`lib/core/subtitle/subtitle_rasterizer.dart` 通过
`osascript -l JavaScript` 调 macOS AppKit（`NSBitmapImageRep` / `NSFont` /
`NSBezierPath`）把每句字幕渲成透明 PNG，再用 ffmpeg 的 `overlay` 叠到画面上。

字体写死 `PingFangSC-Semibold`。**Windows 上这段一行都用不了。**

### 三个选项

| 方案 | 做法 | 优 | 劣 |
|---|---|---|---|
| **A. 纯 Dart 渲染**（推荐） | `dart:ui` 的 `PictureRecorder` + `ParagraphBuilder` + `Picture.toImage()` → PNG，字体打进 assets | **两平台跑同一份代码 + 同一份字体 = 输出天然逐像素一致**；顺带干掉 osascript 那一串授权坑；预览字幕本来就是 Flutter 画的，**预览与成片能共用同一套排版逻辑** | 描边效果要对照现有 JXA 的两遍绘制逐一还原 |
| B. ffmpeg libass / drawtext | 字体文件打进包，交给 ffmpeg 渲 | 不需要在 Dart 里做排版 | 依赖 ffmpeg 构建带 libass（**新版 Homebrew ffmpeg 就不带**，这正是当初绕开它的原因）；折行/描边的控制力差；预览和成片仍是两套排版 |
| C. C# / PowerShell + System.Drawing | Windows 侧另写一套 | 直接 | **两边必然不一致**，违反「成片逐像素一致」。不推荐 |

### 如果走方案 A，几个要点

**描边的两遍绘制要原样搬**。现在 JXA 的做法（`:212-226`）：
先用 `NSStrokeWidth` **正值**画粗黑边打底，再画实心字芯（字芯自身再带一圈
同色细描边撑字重）。**不能用负值一遍画**——描边一粗会吃进字的内部。
Flutter 里的对应写法是 `TextStyle.foreground` 给一个
`Paint()..style = PaintingStyle.stroke` 的画笔，画两遍。

**坐标系要注意**。AppKit 原点在**左下**，代码在 `:242-250` 专门做了到 ffmpeg
左上原点的翻转。**Skia/`dart:ui` 是左上原点，这段翻转逻辑要去掉**，
不然会上下颠倒。

**`sidecar` 文件可以整个删掉**。毛玻璃预设的文本框位置现在是 JXA 写一个
`.box` 旁文件、Dart 再读回来（`_readBox`，还带「读不出就退化为无遮罩」的兜底）。
Flutter 版直接能拿到 `Paragraph` 的 metrics，**这一整套没必要留**。

**字号是千分比**。`spec.fontSize` 来自 `SubtitleStyle` 的千分比换算
（截图里显示「字号 34‰」），换实现时这个换算不要改。

### 验收方式（这条最重要）

> **改之前先用现有 JXA 版跑一批样张存档，改完逐张比。**
>
> 字体换了必然有差，这是预期的；但**排版、位置、描边粗细、折行点、
> 底条圆角必须对得上**。
>
> 这块**不能靠单测判绿**——得出图给人看。
> `CLAUDE.md`：「UI 改动要真机跑起来截图核对，不允许只报『测试通过』。」

### 顺带的好处

方案 A 做完，**macOS 侧也换过去**。这样：
- 两边成片字幕天然一致
- 干掉 `osascript` 这个不稳定依赖（`:143-151` 的注释记录过
  「报了成功却没落下文件」的真机故障）
- 干掉「去系统设置 → 隐私与安全性 → 自动化放行」那一整类用户困惑

## 6.4 建议的做法：先收敛，再分叉

### 问题

现在 **0 处 `Platform.isMacOS`**。这既是优势也是陷阱：

- **优势**：说明平台耦合点少且集中，没有散落的条件分支要清理
- **陷阱**：所有分歧点都得**新开**。如果一边移植一边就地撒
  `if (Platform.isWindows)`，撒到第三十处的时候，两边就是两个软件了，
  「长期双平台并行 + 功能对齐」就守不住了

### 建议

**把所有跟 OS 打交道的东西收敛成一组接口**——就像这个项目已经对产物清单做过的
那件事（`TaskArtifacts` 收敛成唯一一份，「新增一种产物只改那一处」）。

大概是这样一层（名字随意，重点是边界）：

| 接口 | 收口什么 | 替掉现在的什么 |
|---|---|---|
| `PlatformPaths` | home / 应用数据目录 / 桌面 / 视频目录 / 用户级 bin / 剪映草稿根 / 临时目录 | 17 处 `Platform.environment['HOME']`、`cli/data_dir.dart` 的手工路径复刻 |
| `PlatformShell` | which / 在文件管理器中显示 / 打开文件 / 拉起外部 app / 进程存活 / 硬链接 / PATH 分隔符 | `/usr/bin/which`、`open` ×11、`ps -p`、`/bin/ln`、硬写的 `:` |
| `PlatformTools` | ffmpeg / ffprobe / miaoa / audio-separator 的发现与分发策略 | `MediaToolsLocator` 的搜索目录 + `InstallRecipe` 表 |
| `PlatformUpdater` | 自更新（两边实现完全不同，sha256 校验共用） | `core/update/*` |
| `SubtitleRasterizer` | 字幕渲字（见 6.3，换成跨平台实现后**不再需要平台分支**） | `osascript` + JXA |

**这一层大概十几个文件，业务代码一行不用改**——靠把现有 helper 函数的实现
换掉（同名同签名）。

### 为什么这个顺序值得

做完之后，Windows 那边的任务能用一句话说清：

> 写 5 个实现类 + 一条 PowerShell 分发链 + 把内置 ffmpeg 打进安装器。

而不是「读懂 8.9 万行再想办法」。

附带的好处是**功能对齐不再靠人盯**——同一组契约测试可以跑两边的实现，
少实现一个方法就是红的。详见 `07-对齐怎么守.md`。

> **但这是建议。** 如果接手方判断先跑通再收敛更快，那也成立——
> 前提是**收敛这件事要排进计划，不能无限延后**。
> 散落的 `Platform.isWindows` 每多一处，收敛的成本就高一分。

## 6.5 外部工具的分发策略

### ffmpeg / ffprobe —— **产品决策：内置进安装包**

44 处调用的刚需，没它什么都干不了。Windows 上没有 Homebrew，
winget/scoop 在国内下载慢且版本不可控。

**决策：把 `ffmpeg.exe` / `ffprobe.exe` 直接打进安装包**（约 +80–120MB）。
- 用户装完就能用，零配置、零镜像源问题
- **版本可控**——这一条对「成片逐像素一致」是必要的：
  不同 ffmpeg 版本的缩放算法、x264 默认参数会让编码结果有差别
- 用 **LGPL 构建**即可满足分发要求

**实现上**：在 `PlatformTools` 里加一条「内置优先」通道——
先看 `<安装目录>\tools\ffmpeg.exe`，找不到才走 PATH。
`MediaToolsLocator` 现有的缓存 + `forgetMisses()` 机制**保留**，设计是对的。

> ### ⚠️ 一条要记进待办的风险
> 这个决策意味着 **Windows 内置、macOS 仍靠 brew**，两边 ffmpeg 版本会不一样。
> 这跟「成片逐像素一致」有轻微冲突。
>
> **建议**：等 Windows 跑通之后，把 macOS 也改成内置，**两边锁同一个
> ffmpeg 版本**。不阻塞移植，但不要忘。

### miaoa CLI —— **外部未知数，先去问**

这是替换裂变的素材来源，没有它整条线断掉。现在靠
`curl -fsSL https://miaoa.mininglamp.com/api/cli/install.sh | bash` 装。

两条路：
1. **让 miaoa 团队出 Windows 二进制 + `.ps1` 安装脚本** —— 最省事
2. **改走 REST API 直连** —— 架构文档当初就留了这条退路
   （「miaoa REST API（**或**内置 miaoa CLI 子进程）」）。
   好消息是 **`MiaoaGateway` 是唯一出入口且有架构测试守着**，
   换实现只需要动这一个文件

### audio-separator —— 可以晚做

人声分离（换音色时把原声里的人声剥掉）。uv 有 Windows 版，理论可装。

> **Windows 上 CUDA 版是有意义的**（macOS 上没意义，所以配方里写死了 `[cpu]`）。
> 这是 Windows 相对 macOS 的一个**性能优势**，值得利用。

如果第一版先不做人声分离，要**明确把受影响的功能禁用并说明原因**
（换音色、配乐盖住的段落用纯人声），**不许静默降级**。

### 编码器 —— 不要动

一律软编 libx264，**两边完全一致**。
不要在 Windows 上默认启用 NVENC/QSV——那会让两边成片不一致。
（作为可选项提供是另一回事，但不能是默认，且要在 UI 上说清楚。）

## 6.6 建议的分期

> 这是我会怎么排，供参考。关键是**第一波和最后一波的位置**。

| 波次 | 内容 | 验收方式 |
|---|---|---|
| **零** | **先跑一次 `flutter build windows`**，看能不能编译过 | 编译通过。`windows/flutter/generated_plugin_registrant.cc` 只注册了 3 个插件，说明从没 build 过——先把这个基线拿到 |
| 一 | **P0 那 7 条**：数据目录、PATH 分隔符、工具定位、filtergraph 转义、CLI 控制台编码、窗口尺寸、字幕渲染 | app 能启动、能新建任务、能跑完分析、CLI 中文不乱码 |
| 二 | **字体统一**（两边打包同一份） | **换字体后全页面截图复核，布局不能漂**。这一波会动所有页面，要单独一轮 |
| 三 | 快捷键、`open` → `explorer`、进程存活、`_safeName`、滚动条、DPI | 逐项对照 `05` 的 P1/P2 |
| 四 | 工具分发（内置 ffmpeg）、CLI 安装、自动更新 | 装/更新流程真机跑一遍 |
| 五 | 剪映集成（草稿根 / `os` 字段 / 字体路径 / 拉起方式） | **真的在 Windows 剪映里打开一次草稿** |
| 六 | 打包/签名/分发脚本 | 出一个能发给别人的包 |

**两条排期原则**：

- **字幕渲染放第一波**（不是最后）。它是唯一「不换就无解」的，而且换完
  macOS 侧也要跟着换、要出图对比——越早暴露越好。
- **字体统一单独一波**。它会让所有页面的布局动一次，混在别的改动里就说不清
  是谁造成的漂移。

## 6.7 几条容易踩的坑（都是这个项目已经踩过的）

### 构建必须走脚本

macOS 上踩过**三次**：裸 `flutter build macos --release` 出来的产物
没有 AI 凭据，用户打开看到「尚未配置 AI 服务」并以为软件坏了。

云端凭据只在编译期由 `scripts/build_macos.sh` 从 `.secrets/` 用
`--dart-define` 注入，**一共 8 个**（3 个 AI key + 5 个更新 TOS 配置）。

**Windows 构建脚本必须照样注入这 8 个。** 裸 `flutter build windows` 只许用于
本地编译验证，**不能给人用**。

### 不要把调试构建留给用户

macOS 上踩过**两次**：调试构建不带凭据和内置 CLI，用户接手会看到
「未配置/未包含」的降级提示。验证结束后必须换成 Release 产物。

### 外部命令的参数至少手跑一次

真机踩过：`codesign` 没有 `-q` 参数，假 runner 验不出来，真机端到端才逼出来。

**Windows 上要手跑一遍的**：
`where.exe`（多行输出）、`tasklist /FI`（**进程不存在时退出码也是 0**）、
`explorer.exe`（**成功时也返回非 0**）、`mklink /H`（跨卷会失败）、
`Expand-Archive`（路径含中文/空格）。

### 存了却不报最要命

给 Agent 的 JSON 里少一个字段，Agent 查到的空**看起来正好像「没问题」**。
加字段必改 `lib/cli/task_view.dart`，有架构测试
`task_view_completeness_test.dart` 守着。

### 同一条任务不能有两个写入方

整份对象落库，谁后写谁赢，改动会被悄悄抹掉且不报错。
这是 `TaskLock` + `AgentRequest`（界面在场时写操作委派给界面）那套机制存在的理由。

### 验证先用小样本

一次真实分析约 **50 次 AI 调用、几毛钱、几十秒**。
别拿真片子反复试没修完的功能。

## 6.8 关于「重构」

用户提到那边可能会做重构。几点供参考：

**现成的切入点**（都超过了 `CLAUDE.md` 里 800 行的上限）：
`director_page.dart` 5157 行、`workbench_page.dart` 3230 行、
`line_board.dart` 2031 行、`script_doc.dart` 1719 行。

**但建议先跑通再重构。** 理由：
- 这 4,366 项测试（含 52 条架构守卫）是移植期唯一的安全网。
  重构和移植同时做，测试红了分不清是谁造成的
- 这些大文件里埋着大量**真机踩出来的注释**（「真机上撞过三次」「白烧三个版本号」）。
  重构时要把这些注释带走，不能丢

**不要动的边界**（它们是刻意设的，有架构测试守着）：
- CLI 不许 import `package:flutter`
- miaoa 子进程只许 `MiaoaGateway` 起
- 产物清单只有 `TaskArtifacts` 一份
- 画面来源只问 `baseOf()` 一处
- 取段规则只有 `CandidateTrim` 一处
- 预览与导出共用 `AudioTrackBuilder`
- 代理只用于预览，导出走原始素材
