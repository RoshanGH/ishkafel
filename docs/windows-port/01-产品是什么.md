# 一、这个软件是什么

> 给接手 Windows 版的人看的产品介绍。
> **不要跳过这一节。** 这个项目里几乎每一个不寻常的设计背后都有一条产品判断，
> 不知道那条判断，移植时会把它当成可以简化的枝节顺手改掉。
>
> 原始材料：`docs/2026-09-11-路演.md`（产品判断）、`CLAUDE.md`（工程准则）、
> `docs/术语表.md`。本文是为交接重新组织的自包含版本。

## 1.1 一句话

**把一个熟练编导挑镜头的判断力，做成任何人都能调用的东西。**

具体地说：拿一条现成的竖屏口播短视频，**台词与配音一个字不动，把画面全部换成
新素材**，一次产出若干条结构相同、画面全新的片子；或者反过来，从一段台词开始，
造一条全新的片子。

---

## 1.2 为什么存在：AI 的能力边界画在哪

| AI 今天做得到 | AI 今天做不到 |
|---|---|
| 准确理解你的话术、你要的情感 | **对视频做精细化的裁剪操作** |
| 理解它看到的视频里有什么内容 | 帧级的取舍与手感 |
| 理解画面表达的情感 | |
| 理解口播说的是什么意思 | |

所以「AI 剪视频」今天出来的东西还是粗糙的——**不是因为它不懂，是因为它手不稳。**

结论：**不要让 AI 去做它做不了的那一段，要把它做得了的那一段彻底接管。**

一条片子的生产是「脚本 → 拍摄 → 剪辑」。剪辑里 AI 做不了精细裁剪，但它可以把
剪辑里最耗时的环节整个取消掉——**找镜头、对齐字幕、镜头替换**。这几件事恰好
全落在「理解」那一侧。

原本一小时的活，缩减到最后**两三分钟到五分钟**的人工精修。

---

## 1.3 关键定位：这是**给 AI Agent 干活的工作台**

```
原始镜头              AI 预处理              生产环节                 人
（人拍 / AI 生成） → （标签 / 画面描述  →  ishkafel 工作台   →   最后 2~5 分钟
                      / 口播台词）          Agent 在这儿干活        精修
```

**有没有这个软件，区别在哪**——这是整个项目最要紧的一条：

| | 没有这个软件 | 有这个软件 |
|---|---|---|
| Agent 怎么干活 | **自己写程序**去实现工作流 | **调用软件里对应的功能** |
| 产出 | 每次现写、每次不一样 | **稳定，而且足够精细** |
| 人要验的 | 它写的那份程序对不对 | 它的**判断**对不对 |

让 Agent 每次现写一套 ffmpeg 流程，等于把「精细化操作」又推回给它——那正是它
做不好的那一侧。软件把这些操作固化成**稳定、帧级正确、有保护的能力**，
Agent 只负责调用与判断。

### 这条定位对移植的直接影响

**这个 app 有两个平级的前端：GUI 和 CLI。**

不是「GUI 为主，CLI 是附属工具」。CLI（`bin/ishkafel.dart` + `lib/cli/`，
1.1 万行，28 个顶层命令）是 Agent 操作这个软件的正式接口，和 GUI 共享
`lib/core/` 的全部领域逻辑。项目里有一条架构测试专门守着：

> **人在界面上能拧的每个旋钮，Agent 都要能拧。** 少一个，测试当场红。

Windows 版**必须同时交付 CLI**，否则这个产品的核心定位就没了。
而 CLI 在 Windows 上有一个会立刻致命的坑：**控制台默认 GBK 编码，
全中文输出会变乱码**，Agent 读到的全是垃圾。见 `05-平台耦合清单.md` P0。

## 1.4 两条生产线

选哪条线，判据只有一个：**原片那个人的声音还要不要。**

| | 有原片 | 没有原片 |
|---|---|---|
| **替换裂变**（审片台）<br>要原声，台词与节奏照搬 | 上传成片 → 分析切分 → 逐镜换素材 | 不用原片，直接从素材拼 |
| **脚本成片**（编导台）<br>不要原声，台词重写、TTS 重念 | 上传参考片 → 提取台词 → 配音配画面 | 直接写台词 → 配音配画面 |

对应两个主页面：
- **审片台** `WorkbenchPage`（`lib/features/workbench/`，51 文件 / 1.56 万行）
- **编导台** `DirectorPage`（`lib/features/director/`，12 文件 / 1.02 万行）

截图见 `ui-baseline/11-审片台.png` 与 `ui-baseline/24-编导台-行带式工作台.png`。

## 1.5 两层切分：这个产品的地基

```
成片
 └─ 台词语义单元（口语叫「分子」，按台词语义切，不按画面切换切）
     └─ 视觉镜头（口语叫「原子」，按画面切换切，严格嵌套在单元内）
```

一句「这个东西能把衣服洗干净」是**一个台词语义单元**，它内部可能过了 3 个
**视觉镜头**：脏衣服 → 正在洗 → 洗干净了。

替换发生在哪一层，决定了它是什么行为：

- **整体替换**（单元层）：画面和声音一起换，时长跟候选走，后面整体后移
- **镜头替换**（镜头层）：只换画面，变速铺满原坑位，**时长一帧不变**，口播照旧

这两层正是 Agent 下判断的坐标系。它说「U2 的 S2 换成这条」，软件保证换完
**时长一帧不差**、字幕重新烧上去、声音不错位。

> **术语一致性是硬要求。** 全仓、全界面、全文档统一用「台词语义单元」和
> 「视觉镜头」，不用「句子/片段/分镜/clip」。见 `docs/术语表.md`。
> Windows 版的任何新文案都要沿用。

### 「底片」——最新的核心概念（0.1.226 引入）

> **底片 = 这一段画面从哪张片子的哪一段来。**

这个概念把上面那张「整体替换 / 镜头替换二选一」的图**推翻了**：

- **整体替换定的是「这一段的底片是谁」**
- **镜头替换定的是「在这张底片上换掉哪一刀」**

它们根本不在同一层，是过去的数据模型把两件事摆成了平级，才必须二选一。

实现上收敛成单元身上一个 `SemanticUnit.baseCandidateId`，解析入口唯一
（`lib/core/replacement/unit_base.dart` 的 `baseOf()`），回退链：

```
1. 底片已固定（baseCandidateId 非空）  → 用它
2. mode == whole && 有候选            → 那条候选
3. unit.hasSource && task.sourcePath  → (原片, unit.startMs, unit.endMs)
4. 否则 null                          → 垫黑场 + 点名
```

改之前，这个问题在**三处各答一遍且规则不一致**（预览、导出、音频），
后果是画面和声音对同一个单元给出不同答案——一边有声一边黑屏。

## 1.6 为什么必须是 Agent，而不是自动化脚本

「自动铺一版」这种整装功能做了——**它只配当草片**。

一条片子要挑 25~45 个镜头，每一镜都要看图判断：

- 像不像参考镜？
- 跟前后连不连得上？
- 素材上烧没烧别人的字？
- 露的是不是竞品的产品？
- 够不够铺满这一句话的时长？

**这是判断，不是规则。** 写死规则挑出来的东西，看一眼就知道不能用。

所以要把编导操作台上的**每一个旋钮**都交到 Agent 手上，事实也一样不少地摆给它
（参考图、ASR 台词、画面描述、时长、烧字、品牌），**判断权归 Agent，
软件只提供能力和保护**。

推论三条，每条都是踩出来的：

1. **人能拧的每个旋钮，Agent 都要能拧**
2. **软件不替 Agent 做判断，也不背着它自己干活**
3. **播报只报 Agent 在做什么**——软件自己跑的活儿不许占那条通道，
   占了人就分不清是谁在动手

## 1.7 可视化模式：它不是日志，它就是产品本身

> 终局是**静默执行**，但通往静默只有一条路：**人得能从头跟着看它是怎么想的。**
>
> 人需要去干涉的时候，你只给他最后的成片去干涉，就已经来不及了。他如果从头
> 跟了你两遍，发现你整个找视频的逻辑都没有问题，那后面就可以写 skills 总结，
> 让 Agent 直接静默执行了。

所以可视化验的是**它的判断逻辑对不对**，不是「它做完了没有」。

最值钱的是**判断类播报**：

> 「标签命中 5318 条太宽，改用画面描述再搜一轮」

这种话是人肯把花钱的活交给静默模式的**唯一理由**。

**这决定了几条 UI 硬要求**（验收标准见 `docs/可视化验收标准.md`）：
- 每一步都要说人话
- 慢步骤要有**带分母**的进度
- 界面要跟着 Agent 走（焦点跟随、自动滚动到正在动的那一行）
- 正在动哪一行要一眼看得出来

机制上：CLI 与 GUI 是两个进程，通过**数据目录里的文件**通信——
任务锁、在场/焦点、播报流、代办请求、UI 动作、唤醒、界面在哪。
详见 `03-代码图谱.md` 第 4.6 节。

## 1.8 最高准则：按商业化 To C 软件的标准做

`CLAUDE.md` 里的原文（**凌驾于其他所有条目**）：

> 这个 app 虽然不对外销售，但必须做到可以直接拿去卖的品质。任何实现、评审、
> 验收，先问一句「这东西如果是花钱买来的商业软件，用户能忍吗」——不能忍就是
> 不合格，哪怕功能上「能用」。

落成五条可执行判据，**每一条都有代码和架构测试守着**：

| 判据 | 具体是什么 |
|---|---|
| **不静默降级** | 影响成片的东西出错就失败并点名，不许悄悄少一段、少一句、拿默认值顶上。可降级的只有预览这类「人还在看着」的环节，且必须把降级说出来 |
| **不做一次性的脏活** | 算过一次的东西落地复用，改动了才重算。缓存一律按**内容指纹**判定——按文件名存在就当命中，会静默放出上一个版本的内容 |
| **不留孤儿数据** | 磁盘上每一份数据都要有人读、有人删。产物清单收敛成唯一一份（`TaskArtifacts`），新增一种产物只改那一处 |
| **状态可见且可操作** | 后台在干活就说清在干什么、到第几步；失败要给原因和重试入口 |
| **自己先验一遍** | UI 改动要真机跑起来截图核对，不允许只报「测试通过」 |

还有一条只能靠人盯出来：

> **「能跑通」离「能用」还有很远。** 流程全绿、测试全过、片子导得出来，但人一听
> 就知道情绪不对、一看就知道镜头切碎了——这类问题不会出现在任何错误日志里。

## 1.9 设计标准

**UI/UX 必须符合 Apple HIG，达到高标准 To C 商业化软件的品质。**

- **对标产品**：剪映专业版、Final Cut Pro、CapCut 桌面版
- **视觉语言**：macOS 暗色模式标准色板、系统语义色、克制的圆角与留白
- **质感**：4pt 网格、细腻的边框（白 11%）、必要的材质感、避免过度装饰
- **布局**：竖屏（9:16）素材为主要工作对象，播放器窄而居中；
  时间线是主操作区，占比充足（参考剪映约 40% 高度）
- **交互**：主操作有明确视觉反馈；破坏性操作有确认；键盘快捷键完备
- **帧对齐（强制）**：时间线上所有切分边界的调整一律**以帧为最小单位**——
  拖拽吸附帧边界、步进按钮 ±1 帧、时间显示精确到帧
- **文案**：中文界面，用语精准克制，不用技术黑话面向用户

## 1.10 技术形态

```
ishkafel.app / ishkafel.exe          ← 一套 Dart 代码编译的原生程序
 ├─ Flutter 自绘 UI（审片台、编导台、双层时间线、预览窗）
 ├─ libmpv（media_kit，多轨预览，硬件解码，逐帧）
 ├─ ffmpeg（子进程：切分 / 抽帧 / 变速 / 合成导出）
 └─ HTTP
     ├─ miaoa（素材检索：标签精确筛 / 画面描述语义搜 / 首帧以图搜图）
     └─ 云端 AI（火山方舟 LLM+Vision、火山 ASR、豆包 TTS）
```

几条关键取舍：

- **不是网页套壳**（排除了 Electron/Tauri），也不是双原生。视频工具的时间线、
  审片台这类 UI 系统控件给不了，必须自绘
- **本地无 Python 算法生态、无本地模型、无 CUDA 依赖**。重活在云端和 miaoa，
  本地只做「UI + 编排 + ffmpeg 合成」
  （唯一例外：人声分离走 `audio-separator`，是个 Python CLI）
- **一律软编 libx264**，明确拒绝了 videotoolbox。
  → **这个决策让移植省了大事**：编码路径在 Windows 上完全一样。
  （NVENC/QSV 是后续的性能机会，不是移植阻塞项）
- **字幕不走 ffmpeg 的 ass/drawtext**（新版 Homebrew ffmpeg 不带 libass），
  而是渲成透明 PNG 再 `overlay` 叠上去。
  → 这个绕法在 Windows 上同样成立且更稳，**但渲 PNG 那一步是 macOS 专有的**
- **使用者永远不接触任何云凭据**：编译期由构建脚本从 `.secrets/` 注入

### 关于「代码已经是跨平台的」这句话

`docs/2026-09-11-路演.md` 第九节写着：

> **Windows 打包**：代码已经是跨平台的，缺的是打包与签名流程。

**这句话低估了工作量。** 实测：`windows/` 目录只有两次 commit，全是
`flutter create` 模板，零自定义代码；全仓 0 处 `Platform.isMacOS`，
意味着所有平台相关的东西都是**按 macOS 硬写的、没有任何分支**。

UI 那 4.3 万行确实基本可以直接编译，但「app 跟操作系统打交道」那一层
（路径、子进程、工具定位、字幕渲染、自动更新、CLI 安装、分发）
要从零做一遍。逐项清单见 `05-平台耦合清单.md`。

## 1.11 使用流程（一条片子从进到出）

```
新建任务 → 分析 → ①切分确认 → ②替换选材 → 审核 → ③矩阵导出 → 交付
                                  └ 或者走编导台：写台词 → 配音 → 配画面 → 导出
```

对应截图：
- `ui-baseline/07~09` 新建任务向导
- `ui-baseline/11~15` 审片台三个阶段
- `ui-baseline/18` 审核候选
- `ui-baseline/19` 矩阵导出
- `ui-baseline/23~29` 编导台

### 真机数字（一条 75 秒的竖屏口播片）

| 事实 | 数字 |
|---|---|
| 首次可进工作台 | **22.5 秒** |
| 这一次分析的 AI 花费 | **约 0.27 元**（50 次 LLM + 1 次 ASR） |
| 切出来的结构 | 4 个台词语义单元 / 25 个视觉镜头 |

这 22 秒里跑完的是：提取音频 → 人声/背景分离 → ASR（句级+字级时间戳）→
镜头切点检测 → LLM 语义切分 → 两层打标。
分析结果按**源文件内容指纹**缓存，同一条片子再导入直接复用。

> **移植期的成本提醒**：一次真实分析约 50 次 AI 调用、几毛钱、几十秒。
> 调试时**先用小样本**，别拿真片子反复试没修完的功能。

## 1.12 一句话记住这个产品

> AI 今天**看得懂**，但**手不稳**。
>
> 我们把它手不稳的那部分固化成稳定、帧级正确的能力，
> 把它看得懂的那部分——找镜头、放位置、定快慢——整个交给它，
> 只给人留下最后那两三分钟。
