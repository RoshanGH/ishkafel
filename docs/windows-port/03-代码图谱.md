## 3.2 核心领域模型

### 聚合根：`RenewTask`

**`lib/core/models/renew_task.dart`（606 行）**

一条任务 = 一个 JSON 文件（`<dataDir>/tasks/<id>.json`）。
**整个 app 里所有持久化状态都挂在它下面——没有第二个聚合根。**

三种形态由字段判别：
- **替换裂变任务**：`sourcePath != null`
- **空白任务**：`sourcePath == null && script == null`（`isBlank`）
- **脚本成片任务**：`script != null`（`isScript`）

状态只有两个：`RenewTaskStatus { analyzing, ready }`。
（文件里写明「项目没有终态，有始有终的是每一次导出 `ExportRecord`」。）

```
RenewTask (core/models/renew_task.dart)
├─ id / seq(#N 短编号) / name / status / createdAt / updatedAt
├─ sourcePath, miaoaVideoId, coverPath
├─ videoInfo              → VideoInfo
├─ units: List<SemanticUnit>
│   └─ shots: List<Shot>
│       └─ trace / boundaryTrace → TagTrace, BoundaryTrace
├─ asrSentences: List<AsrSentence>
├─ script: ScriptDoc?      ← 脚本成片这一整条线
├─ replacementsByUid: Map<String uid, UnitReplacement>
├─ pickedMaterials: List<PickedMaterial>
├─ bgm: BgmPlan            (BgmMaterial / BgmSegment)
├─ voices: VoicePlan
├─ subtitle: SubtitleStyle
├─ subtitleTrack: SubtitleTrack       ← 只存手改过的
├─ materialAudio / sourceAudio        ← 两层声音的全片打底
├─ exports: List<ExportRecord>
├─ unitTagGroups / shotTagGroups: List<TagGroupRef>
├─ project: ProjectRef?
├─ aiUsage: AiUsage
├─ vocalsPath / backgroundPath        ← 人声分离产物
└─ unitTagPrompt / shotTagPrompt / analysisError / firstReadyMs
```

> ### 身份 vs 位置 —— 这份模型里最重要的一条约束
>
> - `SemanticUnit.uid`（`core/models/unit_uid.dart`）是单元的**身份**，永不变
> - `index` 是**位置**，拖一下就变
> - 挂在单元上的一切（替换方案、音色、配乐、手改字幕、生成的配音）
>   **全按 uid 记** → `replacementsByUid`
> - `RenewTask.replacementsFor(units)` / `byUid(units, plans)` 是
>   **uid ↔ 位置唯一的两处翻译点**
> - 落盘时仍按单元顺序写成数组并带 `unitUid`，兼容旧版本

### 两层切分

**`SemanticUnit`（`core/models/semantic_unit.dart`，203 行）**
`uid` / `index` / `startMs` / `endMs` / `transcript` / `tags` / `tagsStale` /
`tagsHandpicked` / `trace` / `shots` / `hasSource` / **`baseCandidateId`（底片）** /
`wholeAudioMode` / `wholeAudioVolume`

**`Shot`（`core/models/shot.dart`，218 行）**

`tagsStale` / `tagsHandpicked` / `trace` / `boundaryTrace` /

### 底片 `UnitBase`

**`lib/core/replacement/unit_base.dart`（235 行）**
设计文档：`docs/superpowers/specs/2026-09-14-底片-design.md`（303 行）

```dart
class UnitBase {
  final String path;      // 视频文件绝对路径
  final int startMs;      // 用它的第几毫秒
  final int endMs;        // 到第几毫秒
```

### 脚本成片模型

**`lib/core/script/script_doc.dart`（1,719 行）** —— 「脚本即成片，**行是唯一概念**」

```
ScriptDoc
├─ lines: List<ScriptLine>
│   ├─ id (稳定身份) / text / manualMs / tags
│   ├─ type: {voiced, visual}   ← 由 text 是否为空【派生】，不是用户选的
│   ├─ voiceId / speechRate（null = 跟随本片基调）
│   ├─ voiceover: LineVoiceover?
```

**行时长是根**，镜头分蛋糕、总长锁死，每镜最少 500ms，邻镜联动。

## 3.3 状态管理（riverpod）

**flutter_riverpod 2.x，全部手写 provider，没有代码生成。**

### 统一的 DI 模式

> provider 定义在 `features/` 各自的文件里，缺省实现是 `null` 或
> `throw UnimplementedError`，**真实实例在 `lib/main.dart` 的
> `ProviderScope.overrides` 里注入**。测试则 override 成假件。

| 文件 | 核心 provider |
|---|---|
| `features/tasks/task_list_controller.dart` | **`taskListProvider`**（全 app 唯一的状态中枢）、`taskRepositoryProvider`、`analysisPipelineProvider`、`taggingServiceProvider`… |
| `features/settings/settings_providers.dart` | `dataDirProvider`、`cacheScannerProvider`、`environmentProbeProvider`、`miaoaAuthServiceProvider`、`toolInstallerProvider`… |
| `features/director/director_providers.dart` | `scriptTranscriberProvider`、`lineTaggerProvider`、`shotSearchServicesProvider`… |
| `features/picking/picking_providers.dart` | `materialFetcherProvider`、`frameCheckerProvider` |
| `features/tasks/environment_banner.dart` | `mediaToolsStatusProvider`（**用 `overrideWith` 而非 `overrideWithValue`**，这样装好 ffmpeg 后 `invalidate` 能重算） |

### 页面内状态不走 riverpod

三个大页面的局部状态用 `ChangeNotifier` + `setState`：
- `SegmentationEditorController`（501 行）—— 审片台的 units/选中/undo-redo 栈，
  操作全部转发给**纯函数** `SegmentationEditOps`（495 行）
- `PickingController` —— 替换方案状态机
- `CandidateSearchController` —— 候选检索与规格探测
- `DirectorPage` 内部直接持 `ScriptDoc` 并做不可变替换

### 持久化：落文件，不落库

**`FileTaskRepository`（`core/storage/file_task_repository.dart`，148 行）**
- 每任务一个 `<dataDir>/tasks/<id>.json`
- `save` 是**原子写入**：先写 `.tmp` 再 `rename`
  ⚠️ **Windows 上 `rename` 到一个被别的进程打开的文件会抛
  `ERROR_SHARING_VIOLATION`**
- `findAll` 把「读盘 + jsonDecode + 重建对象」整批搬进 `Isolate.run`
  （100 条任务从 573ms 降到 131ms）；单条坏文件只跳过并计数
- **落库时机**：工作台每次改动直接落库（防抖 800ms），**没有「保存」按钮**

## 3.4 十个关键子系统

### 4.1 视频分析管线

**入口**：`lib/core/analysis/analysis_pipeline.dart`（538 行）
**装配**：`lib/app/service_wiring.dart` 的 `buildAnalysisPipeline()`

```
PCM 提取 (AudioExtractor, ffmpeg 16kHz 单声道 s16le)
  ├─ 静音谷        SilenceDetector
  ├─ 人声分离      VocalSeparator（audio-separator 子进程，MDX 模型）
  ├─ 镜头切点      ShotBoundaryFinder
  │     ├─ FrameSignalExtractor (画面差分 + 颜色直方图，双判据)
  │     ├─ SceneDetector (ffmpeg scene 分数)   ⚠️ filtergraph 路径转义
  │     └─ BoundaryReviewer (灰区画面交给 Ark vision 复核，有次数上限)
  └─ ASR           VolcanoAsrProvider（火山「录音文件极速版」，字级时间戳）
        ↓
语义切分  VolcanoSemanticSplitter
          （LLM 只按**句子索引**分组、不产时间戳；边界由代码从句子时间戳推导）
        ↓
吸附构树  SegmentationBuilder + BoundarySnapper
          （切点吸附到帧边界/静音谷，镜头严格嵌套进单元）
        ↓ ← 这一刻回调 onUnitsReady，任务放出「可编辑」（26 秒 vs 打标 70 秒）
两层打标  TaggingService（364 行）
          ├─ UnitTagger   (文本，按维度)
          └─ ShotTagger   (多帧 vision：标签 + 画面描述 + 产品品牌 + 烧字)
          受控词表 MiaoaTagVocabularySource
```

配套：
- **`PreparedCache`** —— 按 `sourcePrint`（源文件内容指纹）缓存前半程产物
- **`AiUsageScope`** —— 用 **Zone** 拦住埋在几层之下的所有并发 AI 调用，
  把 token 记到任务头上；失败也结账
- **`AnalysisProgress`** —— `AnalysisStage` 枚举 + `AnalysisProgressSink` 回调

### 4.3 预览播放（media_kit）

**核心**：`lib/core/playback/multitrack_playback.dart`（467 行）

用户原话：「它就不能像剪映一样各是各的吗？播放的时候一起播放」
→ **不再预合成**，三/四条独立轨同时播：

```
MultitrackPlayback
├─ video:  MasterTrack   = MediaKitPlaybackController  ← 主时钟，且永远静音
├─ voice:  FollowerTrack = MediaKitFollower            ← 偏差超阈值才纠一次
├─ bgm:    FollowerTrack                               ← 按 BgmCue 范围启停/循环
└─ source: FollowerTrack?                              ← 素材原声必须独立成轨
```

最后一条是踩出来的：素材原声挂在画面轨上，播到接缝处要重建音频链路，
主时钟当场卡几秒。

- `playback_controller.dart` —— `playRange` 由播放器自己在终点停住
  （外面盯位置必然过头）
- `media_kit_playback.dart` —— 沉淀了一串 mpv 的坑（`keep-open`、eof 后 play
  会从头、销毁竞态会让进程 abort）
- `edl.dart` —— EDL 文本，画面轨靠它把几十段拼起来
- `gap_clip.dart` / `silent_clip.dart` —— 黑场 / 静音垫片（**EDL 不能留洞**）
- `core/ffmpeg/proxy_builder.dart` —— **预览代理**：所有素材转成同一规格。
  **代理只用于预览，导出一律走原始素材**
  （由 `test/core/export/export_uses_original_test.dart` 看守）

### 4.7 CLI 与 GUI 如何共享代码

**入口**：`bin/ishkafel.dart`（`dart build cli`，产物随 `.app` 分发在
`ishkafel.app/Contents/Resources/cli/<arch>/bundle/bin/ishkafel`）

共享机制四条：
1. **共享 `lib/core/`** —— 模型、管线、导出、混音、miaoa 全在 core 里
2. **共享装配逻辑** —— `lib/app/service_wiring.dart` 和
   `lib/core/script/script_service_wiring.dart` 刻意放在可共享位置。
   CLI 用不了 riverpod，就直接调这两个工厂函数
3. **共享数据** —— 两边都读写 `<dataDir>/tasks/<id>.json`
4. **硬边界** —— CLI 的 import 链里不许出现 `package:flutter`

Ctrl+C 时 `_installInterruptHandler` 立刻撤掉在场状态与锁
（「你说停，他就得马上把手拿开」）。

> ⚠️ `bin/ishkafel.dart:417-418` 是**全仓唯一的平台分支**：
> `if (!Platform.isWindows) sigterm.watch()`。这条已经正确处理了。

> ⚠️ **CLI 分发在 macOS 上做了架构分发**（arm64 + x64 两份 bundle + 一个
> shim 脚本），因为 Dart 不支持交叉编译、AOT 快照不能 lipo。
> **Windows 只有 x64（arm64 可选），这整个复杂度可以砍掉。**

### 4.9 自动更新

**`lib/core/update/`（5 文件 / 657 行）**

`app_updater.dart` 的**五步，每步可回滚**：
1. 下载到临时目录
2. **核对 sha256** ← 这一步两边共用，不要省
3. 用 `ditto` 解压（**不用 unzip**，它会丢扩展属性导致签名失效被 Gatekeeper 拦）
4. 验新包签名
5. 旧的先改名留着，新的就位后才删

sealed state：`UpdateIdle / UpdateChecking / UpdateAvailable /
UpdateDownloading(received/total/ratio) / UpdateInstalling / UpdateFailed`

发布侧：`tool/publish_release.dart`（**纯 Dart，可移植**）、
`scripts/publish.sh`、`scripts/bump_build.sh`

由 `test/architecture/update_is_safe_test.dart` 看守。
⚠️ 这条测试断言某个源文件里不含 `Process.run` / `Process.start`，
**可能会挡住 Windows 版实现，注意**。

### 4.10 缓存与产物管理 —— `TaskArtifacts`

**`lib/core/storage/task_artifacts.dart`（231 行）**


## 3.8 给接手者的七条要点

1. **`RenewTask` 是唯一聚合根**，一条任务一个 JSON 文件。改任何持久化字段都要
   同时改 `toJson` / `fromJson` / `copyWith` / `==` / `hashCode` **五处**
   （手写、无代码生成），且 `fromJson` 必须对老存档兜底
   ——旧版本 app 会和新版本并存分发。

2. **身份 vs 位置**：挂在单元上的东西一律按 `SemanticUnit.uid` 记；
   按位置访问只在 `replacementsFor` / `byUid` 两处翻译。

3. **新增一种磁盘产物只改 `TaskArtifacts`**，删任务、孤儿清扫、缓存统计、
   任务复制会自动覆盖到。

4. **动 CLI 依赖链前先跑 `test/architecture/cli_no_flutter_test.dart`。**

5. **构建必须走脚本**。macOS 上是 `scripts/build_macos.sh` / `pack.sh`；
   Windows 上要写等价物，**且必须照样注入那 8 个 `--dart-define`**。

6. **预览与导出共用同一个混音器**（`AudioTrackBuilder`）和同一套缓存。
   「听到的就是要交付的」是硬约束，**不要为预览另写一条路**。

7. **代理（`proxy/`）只用于预览，导出一律走原始素材。**
