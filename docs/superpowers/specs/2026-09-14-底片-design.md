# 底片：每一段画面都有一张底片，底片可以切分、可以精修

**日期**：2026-09-14
**状态**：四个阶段全部落地（2026-09-14）

---

## 一句话

现在「整体替换」和「镜头替换」是平级的二选一。**它们其实不在同一层**：
整体替换定的是「这一段的底片是谁」，镜头替换定的是「在这张底片上换掉哪一刀」。
把这一层关系显式建模出来，插入段、空白任务、整体替换三条各自为政的路
收敛成同一条。

---

## 从哪儿来的

产品负责人的原话：

> 我既然是添加的一个空的台词语义单元，这个台词语义单元可不可以支持替换分镜？
> 现在是不行的……我添加的一个台词语义单元，它是空的，它本身选一个原始的台词
> 语义单元的分镜，它是没有被另外一个分镜、一个真实的分镜替换过的，所以我觉得
> 它应该是可以走切割，然后打标的这一套流程，然后去替换里面的分镜。

他推测挡路的是「系统认为它被替换过」。**实际不是**——挡路的是
`PickingController.canUsePerShot`：

```dart
bool get canUsePerShot => currentShotCount > 0;
```

手加的单元 `shots = []`，所以没有可替换的对象。这个区别很重要：
**不需要拆任何一把锁，只需要让这个单元有分镜。** 一旦 `shots` 非空，
现有 perShot 那条路原封不动就能用。

顺着往下推，就发现「底片」这个缺失的概念（见下），于是产品负责人选了
B 方案：不是给插入段打补丁，而是把底片理顺。

---

## 现状：「这一段画面从哪儿来」被三处各自回答

同一个问题，三个地方各写了一遍，规则还不完全一致。

### 预览（`track_plan_builder.dart:106-215`）

```
whole 有候选  → 整段用素材，时长跟素材走，sourceStartMs 填原单元的假坐标
!hasSource    → 跳过画面、垫黑场、记 unplayable
否则          → 按 shots 逐段取 task.sourcePath
```

### 导出（`export_runner.dart:_renderSegment`）

```
segment.isOriginal    → trimOriginalVideo(source: task.sourcePath)
shotIndex == null     → wholeReplacementVideo（原样接，不变速、不烧字幕）
shotIndex != null     → fitCandidateVideo（变速对齐坑位 + 烧字幕）
```

### 音频（`audio_track_builder.dart:_unitParts`）三选一

```
整体替换的单元 → 素材自带音频，整段取用
换过音色的单元 → 生成的配音
其余          → 原片音频（被配乐盖住换纯人声）
```

**`hasSource` 在全仓有 32 处引用**，大部分是这同一个判断的变体。

## 目标模型

### 底片

```dart
/// 这一段画面的底片：切分、抽帧、打标、镜头替换全都在它上面做
class UnitBase {
  /// 视频文件绝对路径
  final String path;
  /// 用它的第几毫秒到第几毫秒
  final int startMs;
  final int endMs;
  /// 它是谁：null = 任务原片的一段；非 null = 挑来的素材（回指
  /// PickedMaterial，清理产物时靠它判断还有没有人引用）
  final int? candidateId;
}
```

### 唯一解析入口

```dart
UnitBase? baseOf(SemanticUnit unit, UnitReplacement r, {...});
```

回退链（**顺序即优先级**）：

1. `unit.pinnedBase` 非空 → 用它（用户点过「切分这一段」，底片已固定）
2. `r.mode == whole && 有候选` → 那条候选（多条时取 preview 那条）
3. `unit.hasSource && task.sourcePath != null` → `(原片, unit.startMs, unit.endMs)`
4. 否则 `null` —— 这一段真的没东西可放（今天的「垫黑场 + 点名」那条路）

**老存档零迁移**：没有 `pinnedBase` 的单元，回退链算出来的正好是今天的行为。

### 镜头坐标不动

`shot.startMs/endMs` 仍然相对**单元**、仍然满足 `shotsStrictlyNested`。
「这一镜取自底片的哪一段」由一个函数算：

```
base.startMs + (shot.startMs - unit.startMs)
```

这样时间线几何、命中测试、帧对齐、字幕分段全都不用动。

## 已定的规则

### 底片多选 ⟺ 没精修

底片照样能多选（= 今天的整体替换选 N 条出 N 条变体），**只要不对它切分**。
一旦点了「切分这一段」，收敛成单条底片——第二条底片切出来的镜头数和切点
都不一样，挂在第 3 镜上的选择无处安放。

这条让 B 从「推翻一条已定约束」变成「在原有行为上长出一层」：
**今天所有任务的行为一个字不变**，只有主动点切分时才提示
「切分之后这一段只能用这一条底片，另外 N 条会取消选中」。

### 换底片：允许，但点名

切好分镜、换了几镜之后再换底片，下面的全作废。不禁止（禁止了人就被锁死在
第一次的选择上），弹确认框写明「这一段已挑的 N 处镜头替换会全部清掉」。

### 切分打标：显式触发

不在选完素材时偷偷跑——那一下要花钱、要等。给一个「切分这一段」按钮，
跑的时候有带分母的进度，失败给原因和重试入口。

### 递归到此为止

底片切出来的第 N 镜，换进来的那条素材**不再往下切分**。一层底片 + 一层镜头。

### 切分在素材自己的时间轴上做

不是在「适配到坑位之后」的片段上做——素材会被裁剪、变速去适配坑位，
在适配后的东西上切，一改倍速切点就全飘了。映射到成片轴是显示/导出那一层
的事，收敛成一个函数。

### 变速规则不变

**底片不变速，替换进来的才变速。** 底片定了这一段多长（=今天「整体替换
时长跟候选走」的既有规则），所以底片切出来的镜头坐标直接就是成片坐标；
镜头替换进来的素材照旧 `speed_fit` 适配到镜头坑位。与今天完全一致。

### 声音：接上已有的两层

上一版做的两层声音正好对得上，不新增层：

| 今天 | 底片模型下 |
|---|---|
| `wholeAudioMode`（整体替换时素材自己的声音） | **底片的声音**，全段打底 |
| `shot.sourceAudioMode`（原片这一镜的声音） | **这一镜底片的声音**，覆盖打底 |
| `shot.materialAudioMode`（替换进来那条素材的声音） | 不变 |

界面文案里「原片这一镜的声音」改成「这一镜底片的声音」。插入段过去没有
这一档（它没有原片），现在有底片了就有了。

## 字幕：底片是素材时不渲字幕（已定 A）

`export_runner.dart` 现在明写：

> **整体替换不渲字幕**（shotIndex == null）：时长跟候选走、和原坑位对不齐，
> 按原片时间戳算的字幕贴上去必然错位

底片被换成素材、又切了分镜之后，这一段的台词还在（真实单元的话），
但时间和新画面对不上了。**已定：与今天一致，这一段不渲台词字幕**，
并在界面上显式标一句「这一段不带台词字幕，要的话手动排时间」——
用上一版做的「字幕时间可编辑」自己排。

否掉的两条，记下理由：

- 按新镜头边界重新均分台词：会造出没人确认过的时间点，与「不静默降级」相抵
- 不排时间就不给导出：太硬，把人锁死在一个本来可选的环节上

## 实现时改掉的两处设计

### 1. 不需要 `pinnedBase` 这个结构，一个 `int?` 就够

原方案打算在单元上挂一个完整的 `UnitBase`。实际只需要
**`SemanticUnit.baseCandidateId`**——「这些镜头是按哪条素材切出来的」。
路径由 `TaskMedia.materialPath` 现算，时长来自 `PickedMaterial`。
少存一份就少一处会和现实对不上的地方。

配套的判据 `hasOwnBaseShots(unit)` = `baseCandidateId != null && shots.isNotEmpty`
收敛成一处，有静态守卫盯着不许再抄第二份。

### 2. 镜头坐标不用改，`ComposedTimeline` 早就按「相对单元的偏移」在算

原方案担心镜头坐标要从原片轴换成底片轴，是这件事的主要工程量。读代码发现
`ComposedTimeline._composedShot` 本来就是
`_starts[unitIndex] + (shot.startMs - unit.startMs)`，而时间线早就禁止用
原片毫秒画像素（`no_source_ms_to_px_test` 守着）。

所以镜头坐标一律保持「`unit.startMs` + 偏移」，取底片第几毫秒由一个式子算：

```
base.startMs + (shot.startMs - unit.startMs)
```

底片是原片时 `base.startMs == unit.startMs`，算出来就是原值；底片是素材时
`base.startMs == 0`，算出来是素材内偏移。**一个式子管两种**，预览、导出、
抽帧、剪声音全用它。

## 顺手修掉的一个既有缺陷

`ComposedTimeline.isReplaced` 原来只看「时长变没变」。素材长度**恰好等于**
坑位时它会判成「没替换」，于是按原片时间戳算的台词字幕被贴到一段素材画面上
——对不上，而且哪儿都不报错。现在底片固定过的单元直接判 true。

## 那「半边」其实本来就通（2026-09-15 补做）

原先判断「有原片的真实单元做了整体替换之后不能精修，要先做坐标解耦」——
**这个判断是错的**，探路测试一跑就清楚了：真实单元固定底片后，成片时间轴、
预览分段、导出段落的底片偏移全都对。原因还是那条——镜头坐标一贯是
「`unit.startMs` + 偏移」，而 `ComposedTimeline` 本来就按偏移算位置，
`unit.endMs` 根本没参与。

真正要补的是散在外围的六处，全是「某处只认原片、不认底片」：

| 处 | 症状 | 修法 |
|---|---|---|
| `SegmentationEditOps` 单元级操作 | 拖边界悄悄放行、拆分直接抛断言 | 固定过底片的单元一律拒绝（界面本来有 `EditLocks`，但命令行不走那把锁） |
| `holdsInvariants` | 要求「末镜头盖满坑位」，把合法数据判成坏的 | 固定底片的单元豁免这一条，其余（首镜贴起点、不许有缝、帧点）照旧 |
| `EditLocks` | 整体替换的单元整个钉死，**镜头也调不了** | 拆成两层：单元层照旧锁，镜头层放行——那些刀口正是这个功能要给的能力 |
| `PickingController.perShotLocked` | 切完分镜却挑不了任何一镜，整件事白做 | 固定底片的不锁；反过来把「底片」那一档锁死，换底片走属性面板 |
| `renew_jianying_plan` | 剪映工程里那几段指回原片的同一个时间点 | 原子轨用底片路径 + 素材内偏移，候选轨不再重复摆同一条 |
| 配音裁剪长度 | 按原片坑位裁，声画从这儿起全错位 | 改用 `ComposedTimeline.durationOf`（这一段在成片里的真实长度） |

## 真机走查逼出来的一个洞：底片被当孤儿清掉

切完分镜再给某一镜挑素材，方案从 `whole` 落到 `perShot`，**底片就不在任何
replacement 里了**。而「已选素材」的收敛按 replacements 走，于是把底片判成
没人引用，连记录带首帧图一起清掉——预览找不到路径，**整段变黑，而哪儿都
不报错**。

判据收敛成 `referencedCandidateIds(units, replacements)`（方案里的候选 +
单元身上的底片），加静态守卫。守卫当场又抓出 CLI 侧 `apply_command` 里
同一份摊平的拷贝。
