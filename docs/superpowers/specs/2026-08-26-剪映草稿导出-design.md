# 剪映草稿导出设计

脚本成篇模块新增「剪映」按钮：把当前这一版方案写成剪映草稿，用户自己在剪映里打开做精修。

## 定位

「导出成片」出的是**片子**（ffmpeg 烧死，改一个转场都要重来）；
「剪映」出的是**工程**（原始素材 + 剪辑参数，剪映里随便改）。
两个出口互补，都从同一份方案派生。

## 核心原则：剪映里看到的 = ishkafel 里的结果

不是「我们做了什么」的报告，是这一版方案的最终状态。用户在 ishkafel 里
调的每一个数，进剪映后就是那个数：

| ishkafel | 剪映 | 语义 |
|---|---|---|
| `shot.speed` | `segment.speed` | 调 0.26× 进去就是 0.26× |
| `sourceVolumeFor(line, shot)` | `segment.volume` | 调 0 就是静音，50% 就是 50% |
| `shot.trimStartMs` | `source_timerange.start` | 框选的起点 |
| `allocMs × speed` | `source_timerange.duration` | 按倍率吃掉多少素材 |
| `shot.allocMs` | `target_timerange.duration` | 在成片上占多长 |

**绝不自作主张**：素材铺不满坑位时按项目原规则（`lineShotGaps`）阻断并点名，
不许自己算一个倍率填进去——那会把「数据有问题」悄悄变成「画面被拉慢了」。

## 剪映格式（全部实测于 VideoFusion-macOS 11.1.0）

草稿目录：`~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft/<草稿名>/`

```
draft_info.json          时间线（tracks + materials），时间单位微秒
draft_meta_info.json     素材库（draft_materials[0].value）+ 草稿元信息
draft_agency_config.json / draft_biz_config.json / draft_settings
draft_virtual_store.json / key_value.json / performance_opt_info.json
timeline_layout.json     附属文件，照即剪那份全套写出，缺了剪映会当残缺草稿
materials/               素材（硬链接落地）
```

四条轨对应关系：

| 剪映轨道 | 来源 |
|---|---|
| `video` | `TrackPlan.video`（画面轨） |
| `text` | 字幕，规则见下 |
| `audio` #1 | `TrackPlan.voice`（口播） |
| `audio` #2 | `TrackPlan.bgm`（配乐） |

每个 segment 要挂一串近乎空的占位对象（`speeds`/`canvases`/`placeholder_infos`/
`sound_channel_mappings`/`vocal_separations`/`material_colors`/`beats`），
缺了剪映打不开。只有 `speeds` 有实值。

## 字幕

**复用 `lib/core/subtitle/subtitle_overlay.dart` 的现成规则**，不另起一套：
去标点（`stripPunctuation`，保护 69.9 这类小数）→ 按镜头边界归属
（`lineSubtitleSegments`）→ 按词级时间戳分屏（18 字上限，优先在标点处切）。

实测 2 号任务：27 行台词 → 65 屏，0 标点，无超长。

## 素材落地

硬链接到草稿目录 `materials/`，同盘不占额外空间，跨盘退回复制。

**为什么必须落地**：剪映是沙盒 app（`com.lemon.lvpro`），读不了
`~/Library/Application Support/com.jichuang.ishkafel/`，直接引用缓存路径
会全部显示「暂无访问权限」。

**为什么用硬链接**：两边完全独立——删 ishkafel 缓存草稿照用，删草稿
ishkafel 缓存照用，两个都删空间才释放。实测验证过。

## 命名

`ishkafel_<任务名>_1` / `_2` / `_3` 递增。不覆盖：剪映打开过草稿就会把
`draft_info.json` 加密，覆盖只会毁掉用户已经做的精修。

## 已验证的剪映行为（踩坑记录）

1. **明文草稿剪映能读**，它自己保存时才加密。
2. **草稿列表刷新靠扫描，不是事件**：启动时必扫（实测 8 秒内认领，复现 3 次）；
   运行中周期扫描，间隔 3~18 分钟不定。
3. **没有「让剪映打开指定草稿」的通道**：URL scheme（13 种格式）、命令行参数、
   文档类型、AppleScript、写状态文件（打开草稿只改日志/埋点/临时文件）、
   FSEvents 触发（4 种手段）——全部验证无效。外部草稿动作只有
   `copy_draft_external` / `delete_draft_external` / `rename_draft_external`，
   **没有 open**。业界方案（pyJianYingDraft）用 UI 模拟点击，且只支持剪映 6 及以下。
   → **所以按钮只负责生成草稿，不拉起剪映。**

## 交互

按钮「剪映」，与「导出成片」并列。点击后：

1. 校验：素材未就绪 / 镜头铺不满 → 直接失败并点名是哪一行哪一镜（不静默降级）
2. loading：素材准备 + 草稿写入，报进度（「正在准备素材 12/83」）
3. 完成：提示草稿名，告知去剪映打开；剪映若正开着，说明需重启才能看到

## 模块划分

```
lib/core/jianying/
  jianying_paths.dart      草稿根目录定位、命名递增
  jianying_ids.dart        UUID / 微秒换算等小工具
  jianying_materials.dart  素材落地（硬链接，跨盘退回复制）+ 素材库条目
  jianying_subtitle.dart   字幕段 → 剪映 text material/segment
  jianying_draft.dart      draft_info / draft_meta_info 的构造
  jianying_writer.dart     主入口：ScriptDoc + TrackPlan → 草稿目录
```

不碰 `director_page.dart` / `line_board.dart`（另一 session 在改），按钮接线放最后一步。
