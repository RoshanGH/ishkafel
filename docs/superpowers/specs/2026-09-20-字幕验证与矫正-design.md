# 字幕验证与矫正：给 Agent 一条基准轴和一个字幕模块

> 2026-09-20 与产品负责人讨论定稿。讨论起点是真机反馈：
> **Agent 产出的成片，字幕控制很差。**

---

## 一、要解决的是什么

### 1.1 现象

字幕烧在**视觉镜头**上，而 ASR 给的是**按时间**切的。两条轴一对齐就出岔子：

- 断句落在镜头边界上，**第二句的最后一个字其实是下一个镜头的第一个字**
- 少一句
- ASR 本身就听错字
- 时间偏移

产品负责人原话：

> 我替换那个分镜，然后我一看它的字幕，它两句话，第二句话的最后一个字
> 其实是下一个镜头的第一个字。这只是一个例子啊，其实还有其他各种各样的问题。

### 1.2 人是怎么解决的——这决定了判据

> 人会把该出现在这个画面里的这个字幕手动矫正过来，即便它读的这个时候
> 不在这个时间里了，这个无所谓的，反正它是给人看的嘛，人能反应过来就行。
> 人在看这个镜头有这个字幕就行。

**判据不是「时间轴精确」，是「人看着这一镜，字跟画面对得上、读得顺」。**

人不修时间，人修「这一镜画面上该出现哪几个字」。

### 1.3 这是过渡期的常态，不是一次性的

> 我们这个软件最终其实是给 Agent 用的，由人过渡到 Agent。而且这个过渡
> 不是一次性结束的，每一个任务都会出现，先是让人操作两遍——人操作两遍
> 是在干嘛呢？其实就是在告诉 Agent 后面该怎么干，相当于打个样。

所以这件事 Agent 必须会干，而**规则由人告诉它**（在 Codex / Claude Code 那头），
软件的职责是**把它做这件事所需要的条件给全**。

### 1.4 软件现在给不了这些条件（三处，全部查实）

**一、Agent 看不见任何一行字幕。**

`task --json` 每一镜报 15 个字段——时间、描述、标签、品牌、声音、谁改的——
**唯独不报字幕**。它只能从 `subtitleCoverage` 知道「这个单元有没有字幕」，
看不到有几条、写的什么、几毫秒到几毫秒、是自动算的还是人改过的。

**二、词级时间戳存了，但不报。**

`AsrSentence.words`（`AsrWord{startMs, endMs, text, confidence}`）盘上就有，
`lib/cli/task_view.dart` 里一次都没出现。这是判断「这个字到底属于哪一镜」
唯一的依据，而 Agent 拿不到。**这是「存了却不报」的第 N 次。**

**三、Agent 改得了字，改不了时间。**

`lib/cli/commands/unit_command.dart` 的 `_subtitle()` 里写着：

> 时间在坑位内平均分——精确到毫秒的调整在界面上做，命令行给一个够用的默认

人在时间线上能一帧一帧拖每一段的起止（`subtitle_edit.dart`），
Agent 只能接受平均分。**这是「某件事只长在界面那条路上」的第七次**，
而且长在最难自动化的那一层。

## 二、判定一：全软件只有一条基准轴 —— 成片帧轴

### 2.1 产品负责人的直觉

> 越往后聊，我越觉得可能整个软件需要一个唯一的恒定的时序轨道的存在，
> 作为所有先后顺序、这种排序的基准。

**方向对，需要精确化。**

不可能只有一条**坐标**——替换裂变的本质就是「画面来自 A、台词来自 B」，
两套原生坐标必然共存。但**可以且必须只有一条基准轴**。

### 2.2 现在实际有四条轴

| 轴 | 量的是什么 | 谁在用 | 存还是算 |
|---|---|---|---|
| 原片毫秒 | 上传的那条参考片 | `unit/shot.startMs·endMs`、`task.asrSentences` | 存 |
| **素材内毫秒** | 挑来的那条素材 | 固定底片后的 shot 坐标、`unit.baseSentences` | 存（**同一批字段**） |
| 成片毫秒 | 最后导出的片子 | `ComposedTimeline`，界面显示的一律是它 | 现算 |
| 镜头内毫秒 | 相对这一镜开头 | `SubtitleLine.startMs·endMs` | 存 |

### 2.3 先说一个雷：第一条和第二条共用同一批字段

`shot.startMs` 到底是原片毫秒还是素材内毫秒，**取决于 `unit.baseCandidateId`
是不是 null**。`task_view.dart` 里这段注释就是在给它打补丁：

> 底片固定过的单元，这两个数是**素材内的偏移**，不是原片位置——
> 照原片去对会对到一段毫不相干的画面

同一个字段名、两种含义，靠另一个字段是不是空来区分。人在界面上看不到这个
区别（界面显示的是成片时间），**Agent 拿到的是裸 JSON**：它照着
`sourceStartMs` 去原片抽帧，抽到的是毫不相干的画面，**而且不会报错**。

**这比字幕问题更早该修**，而且本设计依赖坐标含义明确，所以列为前置项（§7.1）。

### 2.4 判定

> **立一条基准轴：成片帧轴。**
>
> 所有「先后、位置、多长」对外一律用它。其他坐标全部降格为**取材信息**
> （从哪个文件的哪一段取画面），**永不参与排序**。

### 2.5 为什么必须是成片，不能是原片

**手动添加的单元在原片轴上根本没有位置**（`SemanticUnit.hasSource == false`，
原片里没有它）。拿原片轴当基准，这些单元只能排在末尾或者编一个假坐标——
而人恰恰是把它们插在中间的。**成片轴上它们有确切位置。**

整体替换同理：它会改变时长，原片轴上 U2 的位置在成片里已经不成立。

这条其实早就定过一次——「界面上的时间数字一律成片时间」。
本设计只是把同一条规矩推到 Agent 那一侧。

### 2.6 为什么必须是帧，不能是毫秒

**因为要解决的问题本身就是边界问题。**「第二句的最后一个字其实是下一个
镜头的第一个字」——这是在问「这个字属于哪一镜」。

毫秒上回答不了：相邻两段的 `endMs == 下一段的 startMs`，边界那一刻同时
属于两段。帧上是确定的——`FrameSpan`（`lib/core/editing/frame_time.dart`）
是**闭区间**，相邻段不共享任何一帧：S1 = 帧 [0,78]、S2 = 帧 [79,…]，
一个字的起始帧落在哪个区间里就是哪一镜的，**没有歧义**。

另外 29.97 在毫秒上和 30 分不开（`round(1000/fps)` 对两者都是 33ms，
`fpsExact` 这个字段就是为这个加的）。帧序号上分得开。

而且帧对齐本来就是项目的强制要求（`CLAUDE.md` 设计标准）。

### 2.7 这条轴已经造了一半

- `lib/core/editing/frame_time.dart` —— `FrameSpan` / `frameIndex` / `msOfFrame`，
  注释第一句就是「帧域：时间线上的一切以帧为单位，毫秒只是存储格式」
- `lib/core/export/composed_timeline.dart` —— `ComposedTimeline`，成片轴的骨架
  （毫秒、按单元），已有 `composedShotStart/End`

**缺的是把它提升成「全软件对外说话的那套坐标」**，以及一个把两者合起来的
「整条片子的帧轴」对象。

### 2.8 工程帧率：轴必须恒定，不能跟着导出走

导出规格是可改的（`export --fps`）。如果基准轴跟着导出帧率走，
换一次导出规格所有位置全变——那就不「恒定」了。

**定一个工程帧率**：默认取原片帧率（`task.videoInfo.fpsExact`），锁死；
导出成别的帧率时只在导出那一步做一次映射，**编辑期间的轴不动**。

没有原片的任务（拼片 / 脚本成片）取第一条素材的帧率；都没有时取 30。

## 三、判定二：字幕抽成独立模块，不进 `task`

### 3.1 产品负责人的判断

> 字幕这个东西，可以在 CLI 的场景下单独抽离出来作为一个模块。
> 它不需要在这个任务给到 Agent 的时候就直接给到……
> 人第一眼看的是个大致，就是有多少个模块、每个模块有几个分镜被替换了。
> 然后下一步是去验证分镜、看逻辑、一点一点改，到最后的几步才改到
> 背景音乐、字幕这种。

### 3.2 量过了，有数

| 任务 | 单元/镜头 | `task --json` 大小 | `units` 占比 |
|---|---|---|---|
| #1 | 6 / 51 | 17 295 字节 | 99.8% |
| #3 | 4 / 25 | 10 030 字节 | 86% |

96 秒的片子约 500 个词，词级 ASR 每词带起止帧约 60 字节 ≈ **30 KB**。
塞进去整份翻三倍，**而 Agent 第一眼根本不看这些**。

### 3.3 判定

> **`task` 是「现状概览」，不是数据倾倒场。** 字幕的全量数据走独立模块。
> 这跟 `candidates` / `log` / `review` 是同一个形状——没有一个把自己的
> 全量数据塞进 `task`。

### 3.4 但 `task` 里必须留一句信号

否则 Agent 永远不知道该去敲字幕模块——它只会按技能文档走流程，
而不是**因为这条片子真有问题**才去。

与 `analysisError`、`composedUnavailable` 同一形状：

```json
"subtitle": {
  "shotsWith": 38,
  "shotsWithout": 13,
  "handEdited": 4,
  "suspect": 6,
  "note": "有 6 镜的字幕看着可疑（跨镜断字 4、空段 2）。查看：ishkafel subtitle check <任务>"
}
```

**一句话 + 一条去处。不给细节。**

### 3.5 顺带收拢：字幕现在散在两个命令里

- `ishkafel subtitle <任务> --preset blurBox` → 管**样式**
- `ishkafel unit subtitle <任务> --unit i --shot j --text "甲|乙"` → 管**内容**

同一件事两个入口，而且内容那个挂在 `unit` 模块下——**可字幕是镜头层的
东西，不是单元层的**。抽模块正好把这两半收拢到一处。

## 四、模块的命令面

```
ishkafel subtitle check  <任务>                            # 自查：只报机械可查的事实
ishkafel subtitle show   <任务> [--unit i] [--shot j]      # 看：完整报告 / 单镜详情
ishkafel subtitle set    <任务> --unit i --shot j --text "甲|乙"
ishkafel subtitle move   <任务> --from 1:2 --to 1:3 --text "怕"
ishkafel subtitle clear  <任务> --unit i --shot j          # 这一镜不要字幕
ishkafel subtitle auto   <任务> --unit i --shot j          # 回到按 ASR 自动
ishkafel subtitle style  <任务> --preset blurBox --bottom 0.22 --font 0.034
```

### 4.1 写的旋钮以「字」和「镜」为单位，不是帧号

**轴给到帧（读），旋钮给到字和镜（写）。** 这是讨论中定下的。

Agent 实际只干三件事：改这一镜显示哪几个字、把几个字挪到隔壁镜、
这一镜干脆不要字幕。让它说「把『怕』从 U2S3 挪到 U2S4」，
比让它算「把 U2S4 第 1 段起点设到第 79 帧」**安全得多，也更贴近它真正
在判断的东西**。

`move` 是新增的，也是最值钱的一条——它直接对应产品负责人举的那个例子。

#### 4.1.1 改完文字，时间从哪来

Agent 只给文字，时间必须由软件定。**顺序是「先对词，对不上才摊」**：

1. **拿每一段文字去这一镜的词级 ASR 里找对应的词**，用那些词的帧区间
   当这一段的起止。这是准的——字是从那几个词来的。
2. **对不上就在坑位内平均分**（现在 `unit subtitle` 的做法），
   **但必须在返回里说出来**：`"timing": "even", "note": "这几段文字在这一镜的
   ASR 里找不到对应的词，时间是平均分的"`。
3. **`voice.source` 是 `replaced` / `none` 的镜头只能走平均分**，同样说出来。

**不许静静地平均分。** 平均分出来的时间看起来和对齐出来的一模一样，
Agent 无从分辨自己拿到的是准的还是凑的——那正是「静默降级」的形状。

`move` 走同一套：挪过去的那几个字，在目标镜里按它们自己的词级时间落位。

### 4.2 `check` 只报机械可查的事实

```
wordSplit           一个词被镜头边界切成两半（带 spillsInto）
outOfSlot           字幕越出这一镜的帧范围
overlap             两段字幕在时间上打架
empty               零长段 / 空文本段
heardButSilent      这一镜听得到话，却没有字幕
silentButCaptioned  这一镜没有台词来源，却挂着字幕
```

**不报的**：断句好不好看、读着顺不顺、错别字。

> 那些是判断，判断归 Agent。

与 2026-09-20 同日定下的检索原则同源：**软件只报事实，判断权归 Agent。**

### 4.3 错别字这一类，软件只能给判断材料

ASR 自己就听错了，**参照物本身是错的**，机械比对查不出来。软件能给的：

- 这一镜的 `productBrand`（已有）
- 这条任务的标签词表（受控词表，产品名、品类词都在里面）
- `AsrWord.confidence`（已有，从未报出去过）——**低置信度的词是听错的高发处**，
  这是事实，不是判断

Agent 拿这些去认「植源」被听成「值源」。**这件事只有它做得了。**

---

### 4.4 样式旋钮要补齐 `--color`

`SubtitleStyle{bottomRatio, fontRatio, preset, colorHex}` 四个字段，
CLI 只给了前三个。`colorHex` 的注释写着「编导台的六色选择走这里」——
**又一次「只长在界面那条路上」，第八次。**

```
ishkafel subtitle style <任务> --color 33D6A6      # RRGGBB，不带 #
```

## 五、报告长什么样

三条规矩，字段都从它们推出来：

1. **对外只出帧，不出毫秒。** 毫秒退回存储格式。两套数字并存就一定有人对错。
2. **位置一律是成片帧轴上的绝对帧。** 字幕存的是「相对这一镜开头」，
   报的时候换算成绝对。
3. **「听到什么」和「显示什么」分成两块字段，永不混写。**

### 5.1 全片那份 —— `subtitle show <任务>`

```json
{
  "projectFps": "30000/1001",
  "totalFrames": 3218,
  "shots": [
    {
      "at": "U2S3", "unitUid": "u-3f2a", "unit": 1, "shot": 2,
      "frames": [612, 701],
      "tc": "00:00:20:12 → 00:00:23:11",
      "voice": "original",
      "heard": "它虽然贵，但冰箱微波炉里的细菌异味怕",
      "lines": ["它虽然贵", "但冰箱微波炉里的细菌异味怕它"],
      "by": "auto",
      "problems": ["wordSplit"]
    }
  ]
}
```

一镜一行，51 镜约 12 KB——扫得动。**`heard` 和 `lines` 并排摆着，
串字、漏字一眼看出来**：上面这条听到的最后是「怕」，字幕却多了个「它」。

这一层的 `by` 是**整镜的汇总**：全是自动算的就是 `auto`，
只要有一段被改过就报改它的那一方（`human` / `agent`）。
逐段的 `by` 在单镜详情里（§5.2）。

### 5.2 单镜那份 —— `subtitle show <任务> --unit 1 --shot 2`

```json
{
  "at": "U2S3",
  "frames": [612, 701], "tc": "00:00:20:12 → 00:00:23:11", "durationFrames": 90,

  "voice": {
    "source": "original",
    "note": "这一镜的声音来自原片，ASR 可用"
  },

  "heard": {
    "text": "它虽然贵，但冰箱微波炉里的细菌异味怕",
    "words": [
      {"text": "它", "frames": [612, 617]},
      {"text": "虽", "frames": [618, 622], "confidence": 0.98},
      {"text": "怕", "frames": [698, 703], "spillsInto": "U2S4"}
    ]
  },

  "lines": [
    {"i": 0, "frames": [614, 660], "text": "它虽然贵", "by": "auto"},
    {"i": 1, "frames": [661, 700], "text": "但冰箱微波炉里的细菌异味怕它", "by": "auto"}
  ],

  "neighbours": {
    "prev": {"at": "U2S2", "lines": ["再不买就恢复69.9一瓶了"]},
    "next": {"at": "U2S4", "lines": ["它，我用了三年"]}
  },

  "problems": [
    {
      "kind": "wordSplit",
      "note": "「怕」从第 698 帧说到第 703 帧，跨过了这一镜的末帧（701）——后半截落在 U2S4 上"
    }
  ]
}
```

**`spillsInto` 是这份报告最值钱的一个字段**，它是那个真机例子的机械表达。
词级时间戳盘上本来就有，只是从没报出去过。

`neighbours` 给相邻镜的字幕文本——**判断串字必须看到隔壁**。

### 5.3 `voice.source` 必须四态分开

防「三态混成两态」那个洞：四种「没台词」长得一模一样就全完了。

| source | 什么情况 | ASR 能不能用 |
|---|---|---|
| `original` | 声音来自原片 | 能（`task.asrSentences`） |
| `base` | 这一段固定了底片，台词来自素材自己的转写 | 能，用 `unit.baseSentences` |
| `replaced` | 整段替换，画面来自别的素材 | **一个字都不能用**，成片这一段本来也不烧台词字幕 |
| `none` | 手动加的单元（`hasSource=false`），原片里没有它 | 没有来源 |

每一档带一句人话的 `note`。**`replaced` 那档尤其要说清**，否则 Agent 会把
「这一段本来就没字幕」当成漏字去修。

依据：`lib/core/export/subtitle_coverage.dart` 与 `slot_subtitles.dart` 的注释——
整体替换「原样接上、时长随候选，和原坑位对不齐，按原片时间戳算的字幕没法
直接烧上去，于是那一段成片里没有台词字幕」。

### 5.4 整体替换段不给词级 —— 不编假数字

产品负责人已拍板。

镜头替换那一段是变速对齐回原坑位的（有明确映射，词级位置算得准）。
**整体替换那一段时长跟着素材走**——原片那几句话在成片里被拉长或压短了，
逐词的帧位置只能按比例摊，那是近似值。

> **那种段落干脆不给词级**，只给 `voice.source = "replaced"` 和一句
> 「这一段的台词时间在成片里已经不成立」，**不编一个看起来很精确的假数字**。

### 5.5 `by` 字段需要新存储

报告要分 `auto` / `human` / `agent`。

`SubtitleTrack`（`lib/core/subtitle/subtitle_track.dart`）现在**不记谁改的**——
只能区分「改过」（`linesOf != null`）和「没改过」（null）。

复用已有的 `EditStamp{by, at}`（`lib/core/storage/edit_stamp.dart`，
0.1.239 给 `Shot`/`SemanticUnit` 加的那一套），按坑位记一份。

### 5.6 样式那一层：Agent 凭什么感知「位置不合适」

产品负责人 2026-09-20 追问：

> 字幕的字体、大小、位置有没有考虑在里面？如果字幕的位置不合适，
> Agent 能不能感知到这个为什么不合适？还有去调整它的位置或者大小、
> 颜色之类的。软件有没有提供给你感知到这一切东西的能力？

**答：现在没有。**缺口见 §1.4 之外的这三处：

1. **烧字只报内容，不报位置。** `FrameCheck.burnedText` 是 `List<String>`。
   烧在底部才是两层字打架、片子废；烧在右上角只是画面里有别人的文案。
   **位置决定严重程度，而 Agent 拿不到。**
2. **颜色没有 CLI 旋钮**（§4.4）。
3. **我们自己的字幕落在哪儿，报告里没有。** `bottomRatio` + `fontRatio`
   + 字数三者一算就知道，**纯计算，不用看图**——没算就没人知道。

#### 判定：把「位置合不合适」降维成「两个矩形重不重叠」

| 要素 | 怎么来 | 哪一波 |
|---|---|---|
| 我们这一行字的矩形 | `bottomRatio` / `fontRatio` / 字数算出来 | **第一批** |
| 素材烧字的矩形 | `FrameCheck` 带上 bbox（要动 AI 识图与缓存） | **另立一波** |
| 两者重叠 | 前两者一比 | 跟着 bbox 那一波 |

这样看图（§六）就退回它该在的位置：**最后的观感确认**，
不是位置判断的唯一手段。

#### 报告里加一块 `caption`

```json
"caption": {
  "box": {"left": 0.08, "right": 0.92, "top": 0.74, "bottom": 0.80},
  "maxCharsPerScreen": 15,
  "willWrap": false
},
"burned": ["冰冰凉凉的好舒服呀"]
```

`burned` 来自这一镜所选素材的 `FrameCheck.burnedText`（已有）。
**位置未知这件事要说出来**，不能让 Agent 以为「有烧字就一定打架」。

#### `problems` 增补两条

```
captionOverflows    这一行字超过一屏能放的字数（maxCharsPerScreen），会被自动切开
burnedTextPresent   这一镜的素材自带烧录字，我们还要再烧一行；位置未知，要看图确认
```

#### 不做每镜覆盖样式

`lib/core/subtitle/subtitle_style.dart` 的注释已经把理由写死了：

> 真正决定观感的是位置和字号——**同一句话前半句在原片镜头、后半句在
> 替换镜头上，两行字高度差出几十像素才是穿帮。**

每镜各调一套正好制造这种穿帮。位置不合适的正解是三选一：
换 `blurBox` 预设盖住、整片挪位置、或者**换掉那条素材**——
而第三条往往才是对的。

## 六、看图那条路（第二阶段，本设计只留接口）

讨论中确认「两个都要」，但**分开做、分开调**：

- **先用读数据扫全片**（`check` / `show`），Agent 自己圈出可疑的那几镜
- **只对可疑的那几镜看图**：抽这一镜的一帧，**把当前字幕真的叠上去**

看图能查出读数据查不出来的：字被素材自带的烧录字幕压住、一行太长断成
两行难看、字盖住了产品。

**为什么不全看图**：一条片子 25~45 镜，每帧要渲染，太贵，而大部分问题
读数据就能查出来。

本设计**不实现**这条，只保证 §5 的报告里有足够信息让 Agent 圈出候选镜头。
渲染叠字那一步另立设计（已有 `subtitle_rasterizer.dart` / `subtitle_overlay.dart`
可复用，`peek` 命令已能抽帧）。

## 八、怎么验收

### 8.1 架构测试（跟着代码走，不手写白名单）

- 报告里出现的每个字段名，`subtitle_view.dart` 里必须真有对应产出
  （照 `task_view_completeness_test` 的形状：**存了就要报**）
- 手册里写的每条 `ishkafel subtitle X` 都要真能敲
  （照 `script_subcommands_real_test`）
- 取时间的路径只有一条：所有「这一镜在成片里第几帧」都走成片帧轴，
  不许有第二处现算（照 `preview_segments_share_one_spec_test` 的形状）
- `subtitle` 模块的错误文案里不出现「没有权限 / 不许 / 被占用」
  （照 `no_permission_refusals_test`）

### 8.2 真机

拿一条真实任务（#1，6 单元 51 镜，已有整体替换段和手改字幕）跑：

1. `subtitle check` —— 报出来的每一条都要能在界面上肉眼复核
2. `subtitle show --unit --shot` —— `heard` 与界面上听到的对得上；
   `spillsInto` 指的那个字，在时间线上确实跨了镜头边界
3. `move` 一个字到隔壁镜 —— 界面上当场变，导出烧出来也是新的
4. **整体替换段**：`voice.source` 必须是 `replaced`，且**没有 `words`**

### 8.3 判据回到产品目标

> 人在看这个镜头有这个字幕就行。

**最终验收是人看成片**，不是报告全绿。报告只是让 Agent 有得判断。

## 九、与既有决定的关系

- **软件只报事实，判断权归 Agent**（2026-09-20，检索那条线同日定下）——

- **帧对齐（强制）**（`CLAUDE.md` 设计标准）——§2.6
- **不静默降级**——§5.3 四态分开、§5.4 不编假数字
