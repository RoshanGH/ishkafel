# 替换裂变：立一条工程时间线，操作向视频编辑器对齐

> 2026-09-21 与产品负责人讨论定稿。
> **范围：替换裂变。** 脚本成片那条线不改模型，只在交给底层之前自己拍扁。

---

## 一、这是什么，不是什么

### 1.1 产品负责人的定调（原话）

> 应该不是剪映，而是**一个编辑器的框架加上一套工作流**。剪映能干的事情很多，
> 它是一个自定义非常强的工具，而我们这个工具只是**替换裂变**。

> 它其实是把一条**已经验证过**、就是一个**我认可的框架**，进行排列组合进行替换
> 的一个工作流。

> 相当于是在有剪映的基础之上，借助 AI 的能力，**一直到最后一步不得已的时候，
> 才人工去介入**。把这个不得已的场景之前所有的东西，都用程序或者 AI 去解决掉。

> 如果剪映开源的话，我就会在剪映上面去添加这些功能。

### 1.2 所以

**剪映要人自己把素材切成一块一块。我们在人动手之前，用 AI 把该切的切好、
该摆的摆好**——切成台词语义单元、再切成视觉镜头、打好标、配好候选。
等人坐下来，「不得已才需要人做」之前的活已经全做完了。

**通用性在剪映是价值，在这里是缺陷。** 多给一种波纹策略，就是多给一种
毁掉框架的方法（见 §4.2）。

### 1.3 现在为什么是妥协

产品负责人的原话：

> 现在所有的这些都建立在一个**转换**上，它不是一个**直接**放在上面。

现状是四套坐标各活各的：

| 东西 | 坐标 |
|---|---|
| 台词语义单元 / 视觉镜头 | 原片毫秒 |
| 字幕 | 相对**这一镜**开头的毫秒 |
| 配乐 | 单元**下标**区间（全项目唯一还按位置记的，有架构测试钉着） |
| 成片位置 | 每次**现算** |

要说「它在成片第几帧」，每样东西都得转换一次。而人一旦加了模块、调了位置，
所有转换结果全变。

**更要命的是：真实切割一旦发生，这套换算的前提就没了。** 一段被裁过、挪过、
跟隔壁合并过又重新切开——它对应原片的哪一段？没有唯一答案。合并再切开之后，
新的 S1 可能横跨原来 S1 的后半和 S2 的前半，它的「原片毫秒」这个问题本身
就不成立。

**所以位置必须直接存在片段身上。不是因为转换麻烦，是因为真实切割之后根本
没有东西可转换了。**

## 二、从真实剪映草稿验证到的事实

讨论中直接读了仓库里那份真实剪映草稿
（`参考内容/即剪/文案1_0819145117/draft_info.json`），以及产品负责人截图的
草稿设置。以下是**实测**，不是推断：

### 2.1 草稿帧率存在，且可改

剪映「草稿设置 → 时间线参数 → **草稿帧率**」，默认 30.00 帧/秒，
菜单为 **24 / 25 / 29.97 / 30 / 50 / 59.94 / 60**。拉进去的素材统一到它。

草稿文件里对应顶层一个 `fps` 字段。它**不是渲染参数，是时间线的网格**。

### 2.2 单位是微秒，但网格是帧

```
fps = 30            一帧 = 33333.33 微秒
duration = 46866666 = 正好 1406.000 帧

视频轨  target_timerange  53/53  落在帧边界上
音频轨  target_timerange   2/2   落在帧边界上
文本轨  target_timerange   0/54  一个都不对齐    例：start = 10002（0.3 帧）
源内区间 source_timerange        不对齐          例：1589467（47.684 帧）
```

**整份草稿里没有任何帧号字段。**

### 2.3 这三种差别各有道理

- **画面/声音必须吸帧**：一帧只能来自一个源。切点落在帧中间，渲染器必须
  二选一，你看到的结果和你切的位置对不上
- **字幕那 0/54 是自动识别字幕**，人一次都没碰过。人一拖就会落到帧上——
  因为**播放头只能停在帧上**
- **源内区间不能吸**：它是「轴上长度 × 变速」算出来的，吸了等于偷偷改变速比

### 2.4 由此得到的唯一规矩

产品负责人的原话：

> 播放的这个时间计数器如果是帧的话，那我下面也应该是帧。整个轴说某一个点的时候，
> 比如说 1:30，24 帧。我之所以要这个修改，就是为了**统一这个时间的标准**。

> **轴上的一切位置 = 帧。**

## 三、核心模型

### 3.1 一条时间线，几条轨

| 轨 | 片段是什么 | 源 |
|---|---|---|
| **声音轨（主轨）** | **台词语义单元** | 原片的一段 / 配音生成的音频 |
| **画面轨** | **视觉镜头** | 原片的一段 / 挑来的素材 / 空（待填） |
| **字幕轨** | 一行字幕 | 文本 |
| **配乐轨** | 一段配乐 | 曲子 |

**「视觉镜头必须填满台词语义单元」在这个模型里就是一句话：
画面轨必须无缝盖住声音轨。** 不是额外加的规矩，是「画面不许有洞」的自然结果。

### 3.2 片段

```
片段 {
  源       : 原片 | 素材#12345 | 空（待填）
  源内区间 : 源文件里的第几帧到第几帧（**素材自己的帧率**）
  轴上位置 : 时间线第几帧开始
  轴上长度 : 占多少帧
  变速     : (源帧数 ÷ 源帧率) ÷ (轴帧数 ÷ 工程帧率)   ← 算出来的，不存
}
```

**位置直接存在片段上，不再从原片毫秒换算。**

### 3.3 全都用帧

产品负责人定：**全都用帧**。理由三条：

**一、帧对齐是 `CLAUDE.md` 的强制要求，存帧号就是「不可能违反」，
不是「靠纪律不违反」。**

2026-09-20 刚栽过靠纪律的跟头：`ComposedFrames` 把段头对称补好了，两处下游
绕过它调裸函数，真机上 **375/487 对相邻词共享同一帧**。补的那条架构测试
（扫字符串）还漏了 `frameAt`。

仓库里做对了的先例是 `preview_segments_share_one_spec_test`：
「那个类型只能由闸产出——构造函数必须是私有的。**这是编译期的保证，不是自觉**。」

**二、只做安全方向的转换。**
`帧 → 时间` 精确（帧号 × 1/fps）；`时间 → 帧` 才有舍入，而上周那个 bug 就
住在这个方向上。存帧号之后，**舍入只发生在人拖拽落点那一刻**——而那本来
就该舍入，因为人选的就是一个帧。

**三、一个单位、一条轴、零转换。** 这个仓库栽过的坑全在转换上。

#### 舍入规则写死，只此一处

`时间 → 帧` 的舍入**只允许发生在两个地方**：人拖拽落点时，以及导入时把外部
时间戳（ASR、素材时长）帧化。

**两处走同一个函数 `帧号(时刻)`，区间一律表示成 `[帧号(起), 帧号(止) − 1]`。**

这样相邻两段**天然不共享帧、也不留空隙**——前一段的末帧 + 1 就是后一段的首帧，
**而且跟用 `round` 还是 `floor` 无关**。

**2026-09-20 那个 375/487 共享帧的 bug，成因不是舍入方式选错了，是段头和段尾
走了不同的处理**（`FrameSpan.fromMs` 只在段尾做了「回退到严格早于 endMs」的
修正，段头直接四舍五入）。一个函数、一种表示，这类 bug 就不可能再出现。

取 `round`（最近帧）——它离人和 AI 的本意最近。但这只是取舍，换成 `floor`
也一样正确，**前提是两端用同一个**。

#### 两处原本想例外的，按同一条规矩处理

- **源内区间**：用**素材自己的帧**。文件本来就是一帧帧的，ffmpeg 也能按帧定位
- **ASR 词级时间戳**：**报出去和比对都用帧**（从存档派生）。
  **原始 ASR 响应原样留作「原始观测」存档**，改帧率时从它重算，什么都不丢。
  存档只进不出——除了重算，没有第二个读它的地方，免得又冒出一套坐标

### 3.4 工程帧率

跟剪映一样是**一个设置**，可改。默认：

| 场景 | 默认 |
|---|---|
| 替换裂变（有参考片） | **参考片的帧率**——它是被验证的框架，帧率是框架的一部分 |
| 没有参考片 | 30（与剪映一致） |

**改帧率要迁移全部帧号**（按旧帧率换算成时间、再按新帧率取整）。这个代价是
诚实的：改帧率本来就是换网格。

素材的帧率、分辨率、码率**全是取材信息**，只在「从这个文件的这一段取画面」时
出现，**不参与任何定位**。导出/预览时 conform 到工程帧率，而这一步跟变速是
同一次计算（ffmpeg 一条 `setpts`），不多一道工序。

## 四、两条总规则

### 4.1 动基准 → 裁剪，不变速。往坑位里填 → 变速对齐。

裁剪是人在改那个「被验证过的框架」本身，他知道自己在干什么。
替换是往框架的坑位里塞东西，坑位说了算。

### 4.2 替换只给变速，不给波纹

产品负责人的原话：

> 这个视频是 1:30，它是有它的道理的，因为它有它的节奏在，就像电影大多数
> 都是 2 小时一样。不管你这个故事真的有多长，它都会压缩在这个时长里面，
> 或者说这个故事很短，它也会延展到这个时长里面。

**成片总时长是框架的一部分，不是副产品。** 波纹会改总时长，改总时长就是改
节奏，改节奏就把那个被验证过的框架毁了。

**所以「只给变速」不是三种策略里挑了一个省事的，是这个业务里只有这一种合法。**

**这是一次行为变更**：今天整体替换是「原样接上、时长随候选、后面顺移」，
改完是「变速对齐塞进原坑位」。

**连带消掉三件事**：

1. `ComposedTimeline` 塌掉大半——它存在的全部理由就是整体替换会改时长
2. 「算不准」整个消失——坑位多长由坑位说了算，不用等素材下载就知道每一帧在哪
   （现在的 `composedUnavailable` / `framesUnavailable` 不再需要）
3. **整体替换那一段终于能有字幕了**——现在没有，理由是「和原坑位对不齐」，
   对齐之后这条理由不成立。2026-09-20 真机上那 8 条 `silentButCaptioned`
   幽灵字幕跟着消失

### 4.3 不做限制

变速多少都照放、照报数字。产品负责人原话：**「软件只提供功能，不做任何限制。」**
跟「软件不许对 Agent 说不行」是同一条。

候选卡上已经在报变速倍数（`3.9×`），顺带把源帧率也报出来即可。

## 五、操作

### 5.1 单元层：主轨磁吸，不许有洞

| 操作 | 发生什么 | 变速 | 全片时长 |
|---|---|---|---|
| **裁剪**（拖边缘） | 只裁自己，源内区间和轴上长度一起变；后面吸上来 | 不变速 | 变短 |
| **删除** | 拿掉，后面吸上来 | — | 变短 |
| **挪位置** | 拔出来插到别处，其余磁吸补位 | — | 不变 |
| **分割**（播放头处） | 一个变两个，共用同一个源 | — | 不变 |
| **合并**（相邻两个） | 两个变一个 | — | 不变 |
| **新增模块** | 在选中单元**之后**插入一个**源为空**的片段，默认 3 秒（人再裁） | — | 变长 |

**拉伸上限是「它当初切出来的那一段」**——裁短了可以拉回去，拉到边界为止，
被邻居挡住。与剪映一致。

**声音跟着单元走。** 剪短单元，那一段口播也短了，台词跟着变——
**词级时间戳直接截断，不用重跑 ASR。**

### 5.2 镜头层：在单元内部，允许暂时有洞

| 操作 | 发生什么 |
|---|---|
| **合并** | 相邻两镜合成一镜 |
| **分割** | 播放头处切开 |
| **删除** | 拿掉，**留一个洞** |
| **拉伸** | 把相邻的拉过来填洞 |

产品负责人的原话：

> 如果他觉得 S1 和 S2 中间切的不对的话，他应该把 S1 S2 合并，然后自己再去切开。

**改切点的正路是「合并 + 重新分割」**，不是拖那条共用的线。

### 5.3 「未完成」状态

> 我把 S3 删掉了，然后缺了一块，这时候它就**不能导出**，就相当于它这个没有完成。
> 它可以把 S2 拉满，或者把 S2 删掉，把 S1 拉满，不管怎么样，反正**只要台词语义
> 单元是满的就行**。

**画面轨有洞 = 成片有黑帧 = 不许导出，并点名是哪个单元缺多少。**
与「不静默降级、影响成片就直接失败并点名」同一条。

### 5.4 裁剪之后不自动重跑 AI

原本的设想是「剪了单元就整段重跑 AI 切分 + 打标，已选素材全丢」。
核下来这个前提不成立：

U1 是 0–6 秒、镜头切在 0–2 / 2–4 / 4–6，剪成 0–5 秒之后，**视觉切点一个都没动**
——还是 0–2 / 2–4，只是最后一镜变成 4–5。**剪的是尾巴，不是重新剪辑这段画面。**

| | 要不要重跑 | 为什么 |
|---|---|---|
| 视觉镜头切分 | **不用** | 切点没动，只要把超出范围的那一镜裁掉或删掉 |
| 镜头的标签 | 不用 | 画面没变 |
| **单元的标签** | **要** | 台词变了（被剪掉几个字），语义层的标签是照台词打的 |
| 已选素材 | **只丢被裁没的那一镜** | 镜头结构没变，其余挂得住 |

这一下差别很大：一次真片分析约 50 次 AI 调用，而人挑素材更贵。

### 5.5 但要给「主动重跑」的能力

产品负责人要求：**两层各一个按钮。**

| 按钮 | 范围 | 做什么 | 破坏什么 |
|---|---|---|---|
| **重新切分这几段台词** | 选中的单元（或全片） | ASR 重新语义切分 + 打标 | 范围内的单元结构、镜头、已选素材、手改的标签**全丢** |
| **重新切分这一段画面** | 选中单元内 | 视觉切分 + 画面描述 + 打标 | 这个单元内的镜头、已选素材**全丢** |

三条约束：

- **动手前点名会丢什么**（「这 3 镜已选的素材会清空」），不是弹「确定吗」
- **Agent 那头也要有**——人能拧的旋钮 Agent 一个都不能少
- **软件自己不主动跑**，要整段重来是人或 Agent 说了算

## 六、其它轨道

### 6.1 声音

| 东西 | 在哪 | 是什么 |
|---|---|---|
| 原片口播 | 声音轨（主轨） | 单元片段自己的源。剪单元 = 剪它 |
| 配音（换音色） | 声音轨 | 把这个片段的源换成生成的音频，长度对齐坑位 |
| 素材自带的声音 | 画面轨片段自带 | 可开可关、可调音量（现在的 `materialAudio`） |
| 人声/背景分离轨 | 声音轨的另一种源 | 取原片的哪一路 |

「这一镜放哪一路声音」这些开关一个不少，只是从「挂在单元/镜头上的字段」
变成「片段的属性」——跟视频编辑器里每个片段有自己的音量/静音是同一回事。

### 6.2 字幕

字幕轨上的片段。**位置是帧**（§3.3：轴上的一切位置 = 帧）。

2026-09-20 做的那一整套——`heard`（听到什么，事实）/ `lines`（显示什么，判断）/
`spillsInto`（这个字骑在边界上）——**逻辑一个字不用改**，坐标从「帧区间」
换成时间线上的帧区间，跨界判定用半开区间 `[起, 止)`。

**「事实 vs 放置」这条线同时也是「谁该吸帧」那条线**：
`heard.words` 来自原始 ASR 存档（观测），`lines` 是放在轴上的（位置）。

### 6.3 配乐

**位置直接存帧区间**，跟别的一样。加的时候**按模块吸附**——
**吸附是操作辅助，不是存储形式**。

**挪动单元时配乐不跟着走**，与剪映一致（动主轨不影响别的轨）。人想让它跟着，
自己再拖一下。

理由：如果配乐存「挂在哪几个模块上」，它的位置就又是推导出来的了——
那正是要拆掉的东西。这也顺手干掉 `remapBgmAfterMove` 和
`unit_data_follows_uid_test` 里「还按位置搬的只剩配乐一份」那条例外。

## 七、底层怎么收口

导出、预览、剪映草稿、字幕烧录现在被两条产品线共用。

> **底层只认时间线这一种输入。谁进来谁负责把自己拍扁成时间线。**

- **替换裂变**：原生就是时间线，直接交
- **脚本成片**：保持「行 → 参考镜」的结构，交给底层之前**自己拍扁一次**

**转换发生在一个明确的地方**，不是散在底层各处。底层永远只有一套。

**顺带的好处**：我们的时间线和剪映草稿的 `target_timerange` / `source_timerange`
变成同一个形状，那一层转换基本消失。

## 八、迁移

**产品负责人定：A，全部就地转换，老片子不管。**

大部分转换是机械的——现在没人真正「切割」过，每个单元直接变成一个片段
（源=原片，源内区间=它现在的 startMs/endMs 换算成帧，轴上位置=累加），
替换方案变成「这一镜的源是素材 X」。

**已经导出过的整体替换段，重新导会和上次不同**（从「顺移」变成「变速对齐」）。
这是接受的代价。

## 九、Agent 的命令面

人在界面上能做的，一个都不能少：

```
ishkafel unit trim   <任务> --unit i --edge head|tail --to <帧数>
                     # --to 是裁完之后这个单元的总长度（帧），不是裁掉多少
ishkafel unit split  <任务> --unit i --at <帧>
ishkafel unit merge  <任务> --unit i
ishkafel unit move   <任务> --unit i --to j          （已有）
ishkafel unit remove <任务> --unit i                 （已有）

ishkafel shot split  <任务> --unit i --shot j --at <帧>
ishkafel shot merge  <任务> --unit i --shot j
ishkafel shot remove <任务> --unit i --shot j
ishkafel shot extend <任务> --unit i --shot j --edge head|tail --to <帧>

ishkafel analyze units <任务> --units 1,2
ishkafel analyze shots <任务> --unit 1
```

## 十、分批

**每一批交出去都得是能用的。**

| 批 | 做什么 | 风险 |
|---|---|---|
| **一** | **对外统一说帧**。`ComposedFrames` 升格成唯一入口（私有构造），所有对外位置一律帧 + 时间码。**产品行为不变** | 最低。先验证「一个单位零转换」舒不舒服 |
| **二** | **换存储 + 整体替换改变速**。片段模型落地、老任务就地转换 | **行为变更集中在这里**。顺带收掉「算不准」那一类、整体替换段的字幕 |
| **三** | **真实切割 + 编辑操作 + Agent 命令**。裁剪/分割/合并/磁吸/未完成拦截，界面与 CLI 一起 | 最大，可能还要再切 |
| **四** | **底层收口**。导出/预览/剪映/字幕只认时间线；脚本成片自己拍扁 | |

**前两批做完就已经拿到「统一的时间标准」了**；第三批才是「操作对齐剪映」。
