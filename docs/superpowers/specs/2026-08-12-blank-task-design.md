# 空白任务：没有原片，手动加分子，只靠标签拼片

**日期**：2026-08-12
**状态**：已确认，待实现

---

## 一句话

原流程是「原片 → 切分 → 打标 → 按标签找替换 → 换配乐 → 导出」。
空白任务**只跳过第一步**：没有原片，分子手动加、标签手动填，
**从「按标签找替换」往后走同一条路**。

这不是一个平行的新功能，是同一条流水线少了个开头。凡是能沿用的一律沿用，
不能沿用的只有三处（见「原流程用不上的地方」）。

---

## 为什么这条路走得通

翻新流程里原片提供三样东西：

| 原片提供的 | 空白任务怎么办 |
|---|---|
| 台词 → 决定切几个分子 | 手动添加分子 |
| 画面 → 决定镜头切点 | 不需要（一个分子 = 一条素材，不再分镜头） |
| 时长 → 决定每个坑多长 | **由素材决定**——这本来就是「整体替换」的既定行为 |

第三条是关键：`ComposedTimeline.wholeDurations` 早就支持「整体替换改变单元时长、
后面的单元跟着挪」，`TimelineGeometry.axis` 也早就按成片时间轴画格子。
所以「时长跟着素材走」不是新设计，是现成的。

**空白任务里每个分子都是整体替换。** 这一句话推导出后面所有结论。

---

## 数据模型

### 任务

```dart
final String? sourcePath;   // 由非空改为可空。null 表示没有原片
bool get isBlank => sourcePath == null;
```

**为什么改成可空而不是存空串**：空串是个谎，而且不会有任何地方报错。
改成可空之后编译器会把所有假设「原片一定在」的地方逐个指出来——那正是
这次要挨个决策的清单（63 处引用）。

空白任务的其余字段：`videoInfo` 为 null、`asrSentences` 为 null、
`vocalsPath` / `backgroundPath` 为 null、`status` 建出来直接是 `ready`
（不走分析）。`unitTagGroups` / `shotTagGroups` / `project` 照常，
**它们是「上哪儿找素材、按什么词表打标」，跟有没有原片无关**。

### 分子

沿用 `SemanticUnit`，不新增类型。空白任务的分子：

- `transcript` 为空串（没有台词）
- `shots` 为空列表（不分镜头）
- `tags` 由手动填写，词表仍来自 `unitTagGroups`
- `startMs` / `endMs`：见下

### 分子在时间轴上占多长

原片刻度对空白任务没有意义（没有原片可切）。但时间线、命中测试、
配乐区间全都以它为内部坐标，所以要给一个**纯内部的名义刻度**：

- 每个分子在名义刻度上首尾相接，长度 = 它在成片里的长度
- 已选素材 → 长度 = 该素材时长（预览那条）
- **未选素材 → 长度 = 2000ms 的占位**，格子上明确标注「待填」

**为什么占位值不算「编造时长」**：格子上写着「待填」，
而全片时长**不显示成一个确定的数**——显示「已填 3 个共 8.4 秒 · 还有 2 个没填」。
用户任何时候看到的秒数都只统计已填的分子。零宽格子点不到、看不见，
比一个标注清楚的占位格子更糟。

选择变化时重算名义刻度，后面的分子跟着挪。

## 音频：素材级人声分离

### 现有流程的真实行为（读代码确认，非推测）

`AudioTrackBuilder._unitParts` 按优先级三选一：

1. **整体替换的单元** → 直接用那条素材自带的音频，整段取用不裁不补。
   **`covered`（配乐覆盖范围）在这一支里被完全忽略**
2. **换过音色的单元** → 用生成的配音
3. **其余** → 用原片音频；被配乐盖住的段落换成原片分离出的纯人声

### 这里有一个现存缺陷

第 1 支意味着：**在翻新模式下对一个整体替换的单元铺配乐，
素材自带的背景音和新配乐是叠着响的**，没有任何地方拦。
整体替换 + 铺配乐这个组合少有人碰，所以一直没暴露。

空白任务里每个分子都是整体替换，这个缺陷会从边角情况变成默认情况。

### 解法

**对挑中的素材做人声分离**，铺配乐的段落用它的纯人声。

- 只在**真的铺了配乐**的段落才分离。没铺配乐就用素材原声、一个字节不改
  ——沿用现有那条原则：分离是有损的（实测残差 -27dB），
  没换配乐的地方没必要先损一道
- 按**内容指纹**缓存，同一条素材只分离一次
- 分离工具没装 / 分离失败时：**不静默叠加**，如实告知
  「这几段配乐会和素材原声叠在一起」，并给出装工具的入口

**这一改动同时修好翻新模式那个缺陷**，两边走同一段代码。

## 组合与去重

沿用现有的笛卡尔积（`ReplacementPlan.combinationCount`，上限 100）：

- 一个分子可选**多条**素材，每条产出一条变体；其中一条是预览用的
- 配乐**不参与乘法**，多首互为备选、按变体序号轮流取（现有规则，不改）

新增一条硬规则：**同一条素材不能在同一条成片里出现两次**。

- 生成组合时**跳过**含重复素材的组合
- 挑选时**当场提示**「这条已经用在 U2 了」，不等导出才发现
- 全部组合都因重复而作废时**明说**，不静默导出 0 条

这条规则**翻新模式同样生效**——那边现在没拦，同一条素材挑给两个单元会真的
出现两次，那显然不是用户想要的。

---

## 导出前置检查

空分子可以放着不管，添加时**不强制**立刻挑素材。
但导出时必须拦住，并给出两条可执行的路：

> U3、U5 还没有挑素材。
> 删掉这两个分子，或者把它们挑满，再导出。

不静默跳过、不用黑场顶替——那属于「影响最终成片的东西出了错就直接失败并点名」。

---

## 预览

预览是「人还在看着」的环节，可以降级，**但必须把降级说出来**：

- 有空分子时预览**跳过**它，提示条写明「U3 还空着，预览里跳过了」
- 一个分子都没填时，播放器显示空态而不是转圈

## 界面

### 入口

新建任务向导第 1 步「成片来源」现在有两张卡片（本地文件、miaoa 成片库·未开放）。
加第三张：

> **不用原片，从素材拼**
> 手动添加分子、给每个分子打标签，用标签搜出素材拼成新片。
> 适合没有参考成片、只知道要什么画面的情况。

选了它，第 2 步（项目与标签组）照常——**标签组仍然必填**，
它是打标的受控词表，没有它后面挑素材时没有标签可用。

### 工作台

沿用同一个工作台，差别只在：

- **时间线**：格子是分子，未填的画成「待填」样式（虚线边框 + 「待填」字样 +
  已有标签），填了的和现在的整体替换格子完全一样
- **没有镜头那一层**：空白任务的分子不分镜头，检查器里不出现镜头列表
- **顶部**：一条「+ 添加分子」按钮；全片时长显示
  「已填 3 个共 8.4 秒 · 还有 2 个没填」
- **检查器**：选中一个分子时，上半是标签编辑（从 `unitTagGroups` 的词表里选，
  沿用现有的标签选择控件），下半是候选素材面板（沿用 `CandidateTab`，
  检索方式固定为标签）
- **分子操作**：添加、删除、拖动排序。删除挑过素材的分子要确认
  （沿用现有的 `EditConsequenceDialog`）

### 不做的操作

空白任务里没有意义、直接不提供：切分、合并、拖动边界、镜头级替换、
保留原片、换音色（没有台词可换）。

## 命令行

- `ishkafel task <id>` / `candidates` / `export` 要能正常读空白任务
- `ishkafel analyze <id>` 遇到空白任务**直接拒绝并说明**：
  「这是一条空白任务，没有原片可分析。分子和标签在 app 里手动填」
- 这一版**不提供**用 CLI 创建空白任务。等真用起来再说

---

## 明确不做（YAGNI）

- **一个分子放多条素材接在一起**：一个分子 = 一条素材。要更长就再加一个分子
- **导出规格可选**：先沿用现有规格。以后要像剪映那样给一组预设，那是独立的一件事
- **给空白任务配 TTS 口播**：没有台词这条线，等 ④ 台词替换那块做了再说
- **CLI 创建空白任务**

## 测试

- **模型层**：空分子的名义刻度重算、组合去重（含「全部作废」）、
  导出前置检查点名
- **音频层**：整体替换 + 铺配乐 → 走分离；没铺配乐 → 用原声不分离；
  分离不可用 → 如实告知而不是静默叠加
- **界面层**：向导第三张卡片、待填格子的样式与文案、
  全片时长的「还有 N 个没填」、删除已挑素材的分子要确认、
  重复挑同一条素材的当场提示
- **回归**：翻新模式一条都不能挂（2175 条现有测试）

## 风险

**最大的一处是 `sourcePath` 改成可空后的 63 处引用。**
逐个决策，不用 `!` 糊过去——每一处都要回答「这里没有原片时该怎么办」。
糊过去的代价是运行时崩在用户面前，而且报的是空指针，不是人话。
