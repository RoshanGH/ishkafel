# ishkafel 项目方向与架构设计

> 状态：骨干方向已确定，细节待细化
> 日期：2026-07-29
> 术语以 [术语表](./术语表.md) 为准

## 1. 项目定位

ishkafel 是一个**素材生产平台**，核心生产方式是**成片翻新**：

对一条成片（竞品/爆款/自有广告视频）进行分析，按台词语义切分，从 miaoa 素材库中检索同标签素材进行替换，本地合成导出，产出结构相同但画面全新的视频。支持一次导出多条组合变体（矩阵导出）。

**与 miaoa 的关系**：miaoa（前后端，Java Spring Boot + 前端）是素材存放层。素材在 miaoa 中已具备标签、画面描述、ASR 提取结果，可用于筛选检索。ishkafel 是消费端——这正是两者打通的原因。第一版 ishkafel 不做素材入库流程。

## 2. 产品形态

**跨平台本地桌面应用**（Mac / Windows，一套代码），非网页打包壳（排除 Electron/Tauri），非双原生。

第一版工作模式为**审片台**：全手动、逐单元人工确认，不做全自动出片。

## 3. 技术选型

| 层 | 选型 | 说明 |
|----|------|------|
| UI 框架 | **Flutter Desktop** | Dart AOT 编译为机器码，Impeller/Skia 自绘 UI（与 Qt 同属自绘流派），产物为原生 .app/.exe，无浏览器内核 |
| 视频预览 | **libmpv**（media_kit，FFI 调用） | 硬件解码，支持逐帧、多实例对比 |
| 分析与合成 | **ffmpeg**（内置二进制，子进程调用） | 拆条、抽帧、场景检测、合成导出，硬件编码（VideoToolbox/NVENC） |
| AI 能力 | **全部云端 API** | ASR、LLM 语义切分、打标、（后续）声音处理；本地无 Python、无本地模型、无 CUDA 依赖 |
| 素材检索 | **miaoa REST API**（或内置 miaoa CLI 子进程） | 检索三模式：标签精确筛 / 画面描述语义搜 / 首帧以图搜图 |

### 选型理由摘要

- 本应用本质是「UI + 编排 + 本地 ffmpeg 合成」，重活（分析、检索、AI）在云端和 miaoa，本地无需 Python 算法生态。
- 视频工具的 UI（时间线、轨道、审片台）系统控件无法提供，必须自绘——Flutter 与 Qt 同流派，但声明式 UI（与 SwiftUI 心智模型一致）开发效率远高于 Qt。
- 剪辑（调切点、修剪）与合成走硬件编解码，与「AI 用 GPU 跑模型」是两回事，不构成引入 Python 的理由。

## 4. 架构总览

```
ishkafel.app / ishkafel.exe          ← 一套 Dart 代码编译的原生程序
 ├─ Flutter 自绘 UI（审片台、时间线、预览窗、标签组选择）
 ├─ libmpv（FFI，视频预览，硬件解码）
 ├─ ffmpeg（子进程：拆条 / 抽帧 / 场景检测 / 合成导出，硬件编码）
 └─ HTTP 客户端
     ├─ miaoa API（素材检索、标签拉取、按视频 ID 拉片）
     └─ 云端 AI API（ASR、LLM 语义切分与打标）
```

## 5. 生产流程（骨干）

1. **输入**：本地上传视频，或输入 miaoa 视频 ID 由 app 拉取；**导入时选定两个标签组**（台词语义单元标签组 + 视觉镜头标签组，均从 miaoa 拉取）。
2. **统一全处理（自动）**：ASR 提取台词+时间戳 → LLM 语义分组切出台词语义单元 → 用语义单元标签组打标（受控词表）→ 逐帧视觉分析切出视觉镜头 → 用视觉镜头标签组打标。
3. **阶段①「切分确认」**：双层时间线（语义单元轨 + 视觉镜头轨嵌套对齐）。拖大边界编辑语义单元、拖小边界编辑视觉镜头（限制在所属单元内）；属性检查器跟随选中对象。**所有边界修改帧对齐**。两层确认后一次性锁定。
4. **阶段②「替换选材」**：每个单元三种互斥模式——保留原片 / 整体替换（外层）/ 镜头级替换（内层）。进入一方，另一方锁定。候选检索三模式互斥单选：标签精确筛 / 画面描述语义搜 / 首帧以图搜图（两层通用，对接 miaoa content search 的 --public-tag / --by content / --like-image）。候选可多选。
5. **组合因子**：整体替换 = 候选数；镜头级替换 = 单元内各镜头候选数的乘积（如 S1 选 2、S2 保留、S3 选 3 → 因子 6）。
6. **阶段③「矩阵导出」**：全片组合 = 各单元因子的笛卡尔积，**上限 100 条**（超限须删减）；界面实时显示组合数；本地 ffmpeg 逐条合成导出。

## 6. 已定决策清单

- [x] 产品形态：跨平台本地桌面 app（Flutter），排除网页壳与双原生
- [x] AI 全部调云端 API，本地无 Python / 无本地模型
- [x] 合成在本地（ffmpeg + 硬件编码）
- [x] 第一版全手动（审片台），不做全自动
- [x] 两层切分模型：台词语义单元 ⊃ 视觉镜头；导入后统一全处理（两层切分+两层打标），阶段①双层时间线一次性确认，帧对齐
- [x] 打标用 miaoa 标签组作受控词表（两个标签组：语义单元组 + 视觉镜头组）
- [x] 候选检索三模式互斥：标签精确筛 / 画面描述语义搜 / 首帧以图搜图（miaoa 均已支持）
- [x] 两级替换互斥：整体替换 与 镜头级替换 二选一，因子为候选数或镜头候选数乘积
- [x] 矩阵导出：笛卡尔积，上限 100 条
- [x] miaoa 素材已带标签/画面描述/ASR，ishkafel 第一版只做消费端
- [x] 分发方式：不做发版流程（无自动更新、无应用商店），仅手动打包（Mac .app / Windows .exe）直接发给同事使用
