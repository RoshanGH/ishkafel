AI 今天看得懂，
但手不稳

所以别让它去剪。把它看得懂的那一段——找镜头、放位置、定快慢 ——整个交给它；把它手不稳的那一段固化成稳定、帧级正确的能力， 让它调用。ishkafel 就是给 AI Agent 干这件事的工作台。

AI 今天做得到

  • 准确理解你的话术、你要的情感
  • 理解它看到的视频里有什么内容
  • 理解画面表达的情感
  • 理解口播说的是什么意思

AI 今天做不到

  • 对视频做精细化的裁剪操作
  • 帧级的取舍与手感

这就是「AI 剪视频还是粗糙」的原因——不是它不懂，是它手不稳。

有没有这个软件，区别在哪

这是最要紧的一条。

没有这个软件有这个软件
Agent 怎么干活 自己写程序去实现人规定的工作流 调用软件里对应的功能
产出 每次现写、每次不一样 稳定，而且足够精细
人要验的东西 它写的那份程序对不对 它的判断对不对

让 Agent 每次现写一套 ffmpeg 流程，等于把「精细化操作」又推回给它—— 而那正是它做不好的那一侧。软件把这些操作固化成 稳定、帧级正确、有保护的能力，Agent 只负责调用与判断。

两层切分，是这个产品的地基

一句「这个东西能把衣服洗干净」是一个台词语义单元， 它内部可能过了 3 个视觉镜头：脏衣服 → 正在洗 → 洗干净了。 替换发生在哪一层，决定了它是什么行为：

层换什么时长
整体替换（单元层） 画面和声音一起换 跟候选走，后面整体后移
镜头替换（镜头层） 只换画面，口播照旧 变速铺满原坑位，一帧不变

洞察

为什么必须是 Agent，而不是自动化脚本

「自动铺一版」这种整装功能我们做了——它只配当草片。 真正要的是把编导操作台上的每一个旋钮都交到 Agent 手上， 事实也一样不少地摆给它（参考图、ASR 台词、画面描述、时长、烧字、品牌）， 然后判断权归 Agent，软件只提供能力和保护。

推论三条，每条都是踩出来的

一、人在界面上能拧的每个旋钮，Agent 都要能拧。 少一个，它就只能被动接受软件给的默认值——那又退回成规则了。 落地成 27 个顶层命令加一份内嵌手册（ishkafel skill --install 直接装进 Claude Code / Codex 的技能目录），外加一条架构测试： 新加了旋钮却没写进手册，测试当场红。

二、软件不替 Agent 做判断，也不背着它自己干活。

三、播报只报 Agent 在做什么。 软件自己跑的活儿不许占那条通道——占了，人就分不清是谁在动手。

可视化模式不是给 Agent 加日志，它就是产品本身

终局是静默执行，但通往静默只有一条路：人得能从头跟着看它是怎么想的。 人需要去干涉的时候，你只给他最后的成片去干涉，就已经来不及了。 他如果从头跟了你两遍，发现你整个找视频的逻辑都没有问题， 那后面就可以写 skills 总结，让 Agent 直接静默执行了。

—— 产品负责人原话，写进了仓库的 CLAUDE.md

所以可视化验的是它的判断逻辑对不对，不是「它做完了没有」。 最值钱的是判断类播报：

「标签命中 5318 条太宽，改用画面描述再搜一轮」

这种话是人肯把花钱的活交给静默模式的唯一理由

出片这一头

矩阵导出把各位置的候选组合起来批量合成，上限 100 条。 「挑差异最大的」不是随机抽——每个替换位置的候选按配额摊开 （5 个候选出 10 条 = 各 2 次），并保证十条之间的搭配互不重样。

合成在本地跑（ffmpeg + 硬件编码），素材、声音、字幕都在自己电脑上过， 云端只负责 AI 那几步。交付两种形态：直接出 mp4/mov，或者生成 剪映草稿工程拖进去继续精修。

声音这一层

被替换的那一镜，声音是两层，各自四档 （不播放 / 人声 / 背景声 / 原声）：原片这一镜的声音——要那句口播，还是要现场音； 替换素材的声音——要它的现场感，还是要它说的那句话。

两层各选各的，最后按你设的音量相加（不是取平均，各层保持自己的音量）。 叠出来真的过载了会点名是哪一段，不偷偷帮你压—— 那等于软件背着人做判断。

架构守卫是这个项目的特色做法

它不测功能，它扫源码。比如：

  • 导出的六个声音参数，任何一处调用漏传就红
  • core 里让人「点某个按钮」的提示，必须同时给出命令行的走法——命令行那头没有按钮可点，Agent 照做会走进死路
  • 新加的旋钮必须出现在 Agent 手册里

这类洞不是逻辑写错，是加东西时忘了改另一处，只有扫描拦得住。

一个真实例子：为什么这套机制值钱

上周有个 bug：替换镜头的声音跑到了片头，还把前面的口播压小了一半。 两个原因——adelay 挪位之后再 atrim， 会把挪出来的前导静音整段吃掉；amix 默认按路数归一化， 叠三层片头就掉 18dB。

参数看上去全是对的——原来的测试比对 ffmpeg 参数字符串，全绿。 只有真跑一遍把声音合出来、逐秒量电平，这两个错才暴露。修完还剩一道坎： 盘上那些按错规则渲出来的中间产物，指纹没变，重新导出照样被原样取出来用。 所以规则版本也进了缓存指纹——老任务直接重新导出就行。

技术形态

一套 Dart 代码，编译成原生程序

ishkafel.app / ishkafel.exe
Flutter 自绘 UI 工作台、编导台、双层时间线、预览窗
libmpv（FFI） 多轨预览、硬件解码、逐帧
ffmpeg（子进程） 切分 / 抽帧 / 变速 / 合成导出，硬件编码
miaoa 素材库 标签精确筛 / 画面描述语义搜 / 首帧以图搜图
云端 AI ASR、LLM 语义切分与打标、Vision 画面理解、TTS

几条关键取舍：

  • 不是网页套壳，也不是双原生。视频工具的时间线、审片台这类 UI 系统控件给不了，必须自绘
  • 本地无 Python、无本地模型、无 CUDA 依赖。重活在云端和 miaoa，本地只做「UI + 编排 + ffmpeg 合成」
  • 使用者永远不接触任何云凭据。内部版编译期注入公司 key，打开即用；商业化版走托管中转，客户端零凭据
  • 自动更新已上线：装了 0.1.172 以上的人，下次打开设置就看到更新提示

目前正式包只出 macOS（.app，Developer ID 签名）。 Windows 是同一套代码、工程已在仓库里，还没走打包流程。
