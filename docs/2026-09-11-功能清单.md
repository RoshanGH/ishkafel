# ishkafel 功能清单与设计初衷

> 2026-09-11 · 对应版本 0.1.223
> 路演主稿见 [2026-09-11-路演.md](./2026-09-11-路演.md)。
> 这一份是逐模块的详表：**每个功能能干什么 + 当初为什么这么设计**。
> 带 ★ 的是核心功能——拿掉它这条线就不成立。

---

## 怎么读这份清单

每一条都是「**它能干什么**」加「**为什么是这样**」。后半句往往比前半句重要：
这个产品里几乎每个不寻常的设计，背后都有一次真机上踩出来的坑。

模块按人使用的顺序排：

```
新建任务 → 分析 → ①切分确认 → ②替换选材 → 审核 → ③矩阵导出 → 交付
                                    └ 或者走编导台：写台词 → 配音 → 配画面 → 导出
```

---

# 一、进门：新建任务与素材库

## 1.1 ★ 两条线的入口

**能干什么**：新建任务时先选生产线——**替换裂变**（要原片的声音）或
**脚本成片**（不要原片的声音）。每条线又各有「有原片 / 没有原片」两种起点。

**设计初衷**：起点不是模式，只是入口。判据只有一条——*原片那个人的声音还要不要*。
要就走替换裂变（台词与节奏天然一致），不要就走脚本成片（TTS 重念，成片长度
必然与原片不同，这是结构性的）。把这个判断摆在第一步，后面所有分叉都省了。

## 1.2 新建任务向导

**能干什么**：四件事一次填完——素材来源（本地文件 / miaoa 视频 ID）、
**两层标签组**（台词语义单元组 + 视觉镜头组）、两层打标约束（人写的提示词）、
限定在哪个 miaoa 项目下找素材。

**设计初衷**：

- **标签组当受控词表**：AI 打标只许用选定组里的标签。自由发挥的标签没法用来
  检索——打出来的词和素材库里的词对不上，等于没打。
- **打标约束一层一条，不是一组一条**：一层选四个组时，那四个组是同一次打标里的
  四个维度，人想约束的是「这一层要怎么判」这件事本身。每组各挂一条，界面上会
  冒出四个输入框，人得把同一句话抄四遍。
- **项目限定**：素材库里四万多条分镜横跨几十个项目，不限项目搜出来的大多不是
  这条片子能用的。

## 1.3 miaoa 素材库对接

**能干什么**：登录（扫码/账号）、拉取企业与项目、拉取标签库、按三种方式检索
候选素材、把选中的素材下载到本地。

**设计初衷**：miaoa 是素材存放层，素材在那边**已经带着标签、画面描述、ASR 结果**
——这正是路演稿里说的「AI 预处理」。ishkafel 是消费端，第一版不做入库流程。

# 二、分析：把一条片子拆成可操作的结构

## 2.1 ★ 两层切分（台词语义单元 ⊃ 视觉镜头）

**能干什么**：导入后自动跑完——提取音频 → 人声/背景分离 → ASR（句级+字级
时间戳）→ 镜头切点检测 → LLM 语义分组切出**台词语义单元** → 在每个单元内部
切出**视觉镜头** → 两层各自打标。真机实测：75 秒的片子 **22.5 秒**可进工作台，
AI 花费约 **0.27 元**。

**设计初衷**：

- **为什么按台词语义切，不按画面切换切**：一段完整的表达可能跨好几个画面。
  按画面切，换素材时会把一句话劈成两半；按语义切，换的是「这一段要说的事」。
- **严格嵌套**：视觉镜头不可跨单元，单元边界必然同时是镜头边界。两层坐标系
  对不齐的话，Agent 说「U2 的 S2」就指不准东西。
- **切点不信 ASR**：ASR 时间戳只做粗定位（容忍 ±0.5s）。LLM 分完组之后，在
  ±0.6s 窗口内吸附到**本地帧级信号**——优先视觉镜头边界，次选静音谷。
  最终切点来自本地检测，**从机制上免疫 ASR 时间戳漂移**。

## 2.2 分析结果按内容指纹缓存

**能干什么**：同一条片子重新导入，直接复用上次的切分，省掉一次 ASR + LLM。

**设计初衷**：语义切分是 LLM 干的、有随机性——真机上同一个文件导三次切出
3/4/5 个单元。不复用的话方案文件就跨不了任务（`unit 2 shot 3` 在新任务里指向
别的画面），「1:1 复刻」也打了折扣。顺带省真金白银。

## 2.3 断点续跑与后台补齐

**能干什么**：切分一出来就能进工作台干活，**打标在后台继续补**。分析失败有
原因和重试入口；打标中断下次进来会接着跑。

**设计初衷**：人等的是「能开始干活」，不是「全部跑完」。把可用的那一刻提前到
22 秒，剩下的慢活挪到后台。

# 三、工作台（替换裂变）

## 3.1 ★ 双层时间线

**能干什么**：六条轨——台词语义单元、视觉镜头、字幕、配乐、画面缩略图、音频
波形。缩放、平移、跟随播放头；点选任意一块，右侧属性面板跟着变。

**设计初衷**：

- **时间线是主操作区**，占比要足（参考剪映约 40% 高度）。
- **所有时间数字一律成片时间**：时间线画的是原片切分，但整体替换会改变时长，
  显示原片毫秒会和播放器对不上。属性面板里「成片开始/结束」与「取自原片」
  分两行写清楚，**一个标了来源一个没标，最容易让人以为是同一件事**。
- **帧对齐是强制的**：所有切分边界的调整以帧为最小单位，时间码精确到帧
  （`00:17.28` = 17 秒第 28 帧，不是 17.28 秒）。卡片上带图例说明这件事——
  不写清楚人一定读错，30fps 下差 0.65 秒。

## 3.2 ★ 三种替换模式（互斥）

**能干什么**：每个台词语义单元三选一——

| 模式 | 换什么 | 时长 |
|---|---|---|
| 保留原片 | 什么都不换 | 不变 |
| **整体替换**（单元层） | 画面和声音一起换 | 跟候选走，后面整体后移 |
| **镜头替换**（镜头层） | 只换画面，口播照旧 | 变速铺满原坑位，**一帧不变** |

**设计初衷**：这两层是不同的生意。整体替换换的是「这一段要说的事」——所以
候选面板在这一层优先展示台词，人是**按台词挑素材**的。镜头替换换的是画面，
台词与节奏必须原样保住，所以变速对齐、时长不变。进入一方，另一方锁定——
同一个单元两种模式并存，导出时没法判断该听谁的。

## 3.3 ★ 候选检索三模式

**能干什么**：三种互斥的找素材方式，两层通用——

- **标签精确筛**：按这一镜打出来的标签去找同标签素材
- **画面描述语义搜**：用自然语言描述找
- **首帧以图搜图**：拿这一镜的首帧去找视觉相似的

候选可多选（一个坑位备好几条），带时长差徽标（绿=变速容忍内，橙=超限）、
低清徽标、烧字警告、品牌角标。

**设计初衷**：

- **三种不是冗余，是三种不同的判断依据**。标签命中太宽时（真机上撞到过
  5318 条）就换画面描述；描述搜不准就用首帧以图搜图。
- **候选多选是矩阵导出的前提**：一个坑位选 N 条，就是 N 条变体的来源。
- **烧字警告是硬需求**：素材画面上烧着别家的字，换上去再叠一层我们的台词字幕，
  两行字打架，片子直接废。而**素材库的画面描述里一个字都看不出来**——必须看图。

## 3.4 ★ 画面复核（看图问两件事）

**能干什么**：对候选素材的首帧做一次 Vision 调用，一次问清两件事：
**画面上烧着什么字**、**露出的产品是谁家的**。结果落库、进候选卡。

**设计初衷**：这两件事同源——素材库给的描述里两样都看不出来，而且都要等到
成片出来才发现。既然都要看图，就一次问完（多问一个问题几乎不加钱，多跑一次
调用是成倍的）。**品牌一致性**尤其要紧：替换裂变里跨品牌露出会直接出事故。

「认不出来」和「画面干净」必须分得开——认不出来给 null，瞎猜一个牌子比承认
不知道更糟。

## 3.5 属性面板

**能干什么**：跟随选中对象三态显示（单元 / 镜头 / 无选中）。单元上能改台词、
逐帧微调边界、拆分、并入、手填标签、换音色；镜头上能改边界、改标签、
改这一镜的字幕、设两层声音。

**设计初衷**：**逐帧步进按钮而不是拖边界**——切分边界来自分析管线+帧信号，
人要做的是「切、合并、逐帧微调」，在轴上把两段拉来拉去只带来误操作。

## 3.6 ★ 多轨预览（听到的就是要交付的）

**能干什么**：画面轨、口播轨、素材原声轨、配乐轨同时播，按成片时间轴对位。
换方案不重新合成，改一下就能听。

**设计初衷**：**预览的全部意义就是「听到的就是要交付的」**。这条踩过好几次：
「替换分镜的声音」一度只在导出那条路上有，预览压根没有它——人在预览里听着
一切正常、挑好了组合，一导出发现多一层声音，而他找不出原因。

预览必要时可以降级（比如分离轨还没好先放原混音），**但必须把降级说出来**。

## 3.7 字幕层

**能干什么**：换过素材的镜头会重新烧字幕。字幕在预览里是**画面上现画的一层**
（不烧进文件），拖位置、改字号、换颜色、换衬底都即刻可见；字幕文字和时间
都能改——属性卡里按成片时间码输入，时间线上拖分段（放大后一句一段，
可拖左右边缘与整体平移）。

**设计初衷**：

- **为什么现画不烧录**：烧进切片的话，每动一下滑杆都要重渲 → 换播放源 →
  播放器重开文件，转圈几秒、位置归零。用户原话：「这个跳转太煞笔了。」
- **为什么只有换过素材的镜头才有字幕**：没换的镜头，台词字幕烧在原片像素里，
  我们既读不出也不重渲，再叠一层就是两行字打架。
- **为什么能手改**：字幕默认按 ASR 的**词级时间戳**切给各镜，而「哪里断句好看」
  是编导的判断，规则算不对——真机上「了」这个字的声音落在下一镜，那一镜的
  字幕就以一个孤零零的「了」开头。

## 3.8 ★ 两层声音

**能干什么**：被替换的那一镜，声音是两层，各自四档（不播放 / 人声 / 背景声 /
原声）+ 独立音量：

- **原片这一镜的声音**：要那句口播，还是要现场音
- **替换素材的声音**：要它的现场感，还是要它说的那句话

全片打底 + 单镜覆盖两级。

**设计初衷**：用户原话——「我需要用替换分镜的原声，加上参考分镜的人声或者
背景声，排列组合由我自己选。我不想做这么定制化，我要把它拆成功能。」

几条刻意的取舍：

- **没点过 = 自动**（原混音；铺了配乐就换纯人声）。直接把默认写死成「原声」的话，
  人什么都没动、铺了配乐的段落声音反而变差。
- **一旦点了任意一档，就完全按他选的来**——冲突只提示，不替他改。
- **各层相加，不取平均**。取平均的话每叠一层前面的口播就掉 6dB，三层掉 18dB。
  叠出来真过载了**点名是哪一段**，不偷偷压——那等于软件背着人做判断。
- 「不播放」垫的是**等长静音**，不是少拼一段（少一段后面全体提前）。

## 3.9 换音色（TTS）

**能干什么**：按单元换音色，生成配音替换原口播。有音色库、试听、本片基调
（全片统一）+ 单行覆盖，语速可调，配音生成后落库复用。

**设计初衷**：换音色与整体替换**互斥**——前者用 TTS 合成的口播，后者用候选
素材自己的口播，同一段只能要一个。导出前置检查拦下并说明，不静默取其一。

## 3.10 配乐

**能干什么**：横向拖选一段连续的台词语义单元铺配乐，每段独立音量，
**一段可选多首互为备选**（导出多条时轮流用，不是叠着放）。曲库来自 miaoa，
本地缓存。

**设计初衷**：

- **按台词语义单元对齐，不按镜头**：整体替换之后单元还在（只是时长变了），
  镜头没了——按镜头记的区间在那一刻就悬空了。
- **多首是备选不是叠加**：一段选 4 首、导 6 条，就是 A/B/C/D/A/B。总变体数
  只由画面替换决定，配乐不做乘法。
- 被配乐盖住的段落自动改用**分离出来的纯人声**，否则原片背景音和新配乐
  两首曲子一起响。

## 3.11 审核候选

**能干什么**：把这一批挑中的素材摊在一页上逐条过，悬停即播，剔掉不合适的。
剔除结果直接落进替换方案。

**设计初衷**：Agent 挑完之后人要有一个**集中复核**的地方——在工作台里一个个
点开看太慢。剔除落在主流程的替换方案里（唯一真相），不是另存一份回执。

# 四、编导台（脚本成片）

## 4.1 ★ 行带式工作台

**能干什么**：一行台词一个带子，逐行写台词 → 生成配音 → 配画面 → 铺配乐。
台词可以自己写，也可以从参考片里提取。

**设计初衷**：这条线的根是**台词**——「脚本即成片」。节奏由配音决定，
所以配音先于画面：先知道这句话念多久，才知道要配多长的画面。

## 4.2 参考片复刻

**能干什么**：上传一条参考片，提取它的台词、逐行的参考镜头（首帧）、
镜头时长分配，然后照着这个结构去找自己的素材。

**设计初衷**：「照着这条片子做一条」是最常见的需求。参考镜头给 Agent 的是
**看图判断的依据**——像不像那一镜，只有看图才知道。

## 4.3 逐行配画面与时长分配

**能干什么**：一行可以配多个镜头，自动/手动分配每镜占多长；镜头不够铺满
这一行时会点名说清楚。

**设计初衷**：配音时长是硬约束。画面必须铺满，**缺一段不许静默跳过**——
那会让成片少一截而没人发现。

## 4.4 本片基调与逐行覆盖

**能干什么**：全片统一的音色与语速（基调），个别行可以单独改。

**设计初衷**：同一条片子里音色跳来跳去是硬伤。默认统一、例外单设。

# 五、出片与交付

## 5.1 ★ 矩阵导出

**能干什么**：把各位置选中的候选做组合，一次批量合成，**上限 100 条**。
导出前摆出「这几条各用什么」（位置标到 `U2·S2`），导出后列出实际文件名。

**设计初衷**：一个坑位选 N 条素材，就该出 N 条变体去投放测试——这正是
「裂变」两个字的意思。上限 100 条是产品定的闸，超了要人自己减。

## 5.2 ★「挑差异最大的」

**能干什么**：从全部组合里挑 3/5/10/20 条彼此差异最大的。

**设计初衷**：这一条真机上翻过车，值得说清楚。用户原话：「一个镜头选了 5 个
替换，但是导出 10 条全是选用的其中同一个……任何一个替换的位置都尽量不重复。」

根因是三个毛病叠在一起：组合超过上限时掐里程表前 100 条（慢的那一位的候选
根本没进池子）；挑选算法把一个单元的多镜合并成一条素材；「差异」只按素材
长得像不像算（同一批拍摄的相似度接近 1，算法认为换了等于没换）。

现在的规则：**每个位置的候选按配额摊开**（5 个候选出 10 条 = 各 2 次），
配额之内才比距离，收尾还做一轮局部交换把偏斜换平。**看着像不是重复用同一条
的理由——人既然挑了 5 条，5 条就都得露面。**

## 5.3 导出规格与帧率

**能干什么**：分辨率 / 帧率 / 码率 / 编码 / 格式可选，预计大小实时算。
**帧率默认跟着原片走**；手动选到比原片低时会说清楚在丢帧。

**设计初衷**：剪辑软件里「工程帧率」和「导出帧率」本来是同一个数。我们把它
拆成了两个——时间线按原片帧率数帧，导出帧率却写死 30。原片 60fps 的话，人在
时间线上按 60 数帧、一导出变成 30，中间一句话都没有。

## 5.4 出门前的交付拦截

**能干什么**：导出**在进门口**拦下会静默出错的几种情况并点名：整体替换与换音色
冲突、选了音色没生成配音、有配乐却没有人声轨、选了要分离的声音档位却没有
分离轨、手加的单元还没挑素材、同一条素材占了两个位置导致一条都排不出来……

**设计初衷**：**该拦的在进门口拦**。让人先选一遍分辨率码率、点了「开始导出」
才蹦出「没能导出」，是在浪费他的时间。而且这些错的共同点是——
**导出来的片子看着正常，其实不是用户要的**，他发现不了，所以宁可不导。

## 5.5 同名不覆盖

**能干什么**：往同一个目录导第二批时，撞名的文件往后排（`变体1(2).mp4`）。

**设计初衷**：导出目录默认沿用上次导到哪儿，而文件名只由方案名决定——
第二批和上一批一模一样，底下的 ffmpeg 又一律带 `-y`，上一批成片**凭空消失**。
成片是要交付给客户的东西，「数据不能凭空消失」这条在这儿最实。

## 5.6 ★ 剪映草稿交付

**能干什么**：生成剪映草稿工程——分子轨、原子轨、候选轨、口播轨、配乐轨、
字幕，素材一并落地。打开剪映就能继续精修。

**设计初衷**：**我们不做精修**。最后那两三分钟的手感活交给剪映，我们把前面
一小时的活干掉，然后把一份结构完整的工程交出去。草稿名按序号递增、
**从不覆盖**——剪映打开过的草稿会被加密，覆盖会毁掉人已经做的精修。

# 六、给 Agent 的那一面

## 6.1 ★ 全量 CLI（27 个顶层命令）

**能干什么**：`ishkafel analyze / candidates / apply / unit / subtitle / voice /
bgm / export / jianying / script / review / task / todo / ui …`——
**人在界面上能拧的每个旋钮，命令行都能拧**。所有输出是 JSON。

**设计初衷**：少一个旋钮，Agent 就只能被动接受软件给的默认值——那又退回成
规则了。有一条架构测试拿命令清单去对手册：**新加了旋钮却没写进手册，
测试当场红**。照着不存在的命令走，Agent 会以为是环境坏了，而不是文档错了。

## 6.2 ★ 内嵌技能手册

**能干什么**：`ishkafel skill --install` 直接把手册装进 Claude Code / Codex 的
技能目录。手册里写了完整的工作流、每个旋钮的用法、以及**为什么这么设计**。

**设计初衷**：只读不装的话，对话一长 Agent 就会忘掉规则。手册正文是**生成**
进二进制的，有测试盯着它和源文档一字不差——生成物对不上，使用者装到的就是
旧手册，Agent 照着旧文档调新命令，报错还不知道为什么。

## 6.3 ★ 可视化模式（Agent 干活时人在旁边看）

**能干什么**：Agent 每一步在界面上播报「它在做什么」，界面自动滚到它正在动的
那一行并高亮，慢步骤给**带分母的进度**（「全片 23/47 镜」）。人可以随时点
「我来接手」抢回控制权。

**设计初衷**：这是这个产品的灵魂，不是日志。终局是静默执行，但通往静默只有
一条路——人得能从头跟着看它是怎么想的。四条硬指标：每一步说人话、慢步骤带
分母、界面跟着走、「在忙」和「坏了」分得开。

**最值钱的是判断类播报**：「标签命中 5318 条太宽，改用画面描述再搜一轮」——
这种话是人肯把花钱的活交给静默模式的唯一理由。

## 6.4 写锁让位

**能干什么**：Agent 要写任务时，界面**把写锁让出来但留在页面上**，自己转成
只读跟随；Agent 收工后界面把锁拿回来。

**设计初衷**：可视模式要求界面停在这个任务上，而 Agent 写这个任务要求界面
不能停在上面——最该让人看见的那几步，恰恰因为「人在看」而做不了。
让界面退出去腾锁是错解（一退出人就什么都看不见了）。

# 七、后台与运维

## 7.1 自动更新

**能干什么**：发版后所有人下次打开设置就看到更新提示，一键下载安装。
包有 SHA256 校验。

**设计初衷**：**打包和上线是两件事**——打包是内部动作随时可做，上线是对外动作，
产品负责人点头才做。不是每个版本号都要上线。

## 7.2 缓存与产物治理

**能干什么**：设置页能看到各类缓存占用、一键清理；删任务时带走它的全部产物；
启动时扫一遍孤儿产物清掉。

**设计初衷**：磁盘上躺着的每一份数据都要有人读、有人删。真机上量到过：
1.4G 数据里活着的任务只有一条，六条已删任务的封面、人声分离结果（32M/条）、
预览切片全都还躺着——因为清理器写的是 `if (entity is! File) continue`，
把目录整个跳过了。现在**产物清单收敛成唯一一份**，新增一种产物只改那一处。

## 7.3 AI 用量记账

**能干什么**：每条任务记下它累计花掉的 AI 钱（按模型、按服务分开），
任务卡上直接显示。

**设计初衷**：这是花钱的活。人要能随时知道一条片子花了多少——真机上一条
75 秒的片子约 0.27 元。

## 7.4 运行环境自检

**能干什么**：`ishkafel doctor` 与设置页的「运行环境」检查 ffmpeg、人声分离
工具、AI 凭据、miaoa 登录态是否就绪，缺什么说清楚怎么补。

**设计初衷**：「在忙」和「坏了」必须分得开。缺工具就说缺哪个工具，
不要让人对着一个失败去猜。

# 八、贯穿全局的几条规矩

这几条不是某个模块的功能，是**所有模块都要守的**——也是这个产品和
「能跑就行」的软件之间的距离。

| 规矩 | 为什么 |
|---|---|
| **不静默降级** | 影响成片的东西出错就失败并点名，不许悄悄少一段、拿默认值顶上。可降级的只有预览这类「人还在看着」的环节，且必须说出来 |
| **缓存按内容指纹** | 按文件名存在就当命中，会静默放出上一个版本的内容。改了规则就要改指纹——否则装了新版、老任务重新导出，听到的还是老毛病 |
| **不留孤儿数据** | 每一份数据都要有人读、有人删 |
| **状态可见可操作** | 后台在干活就说清在干什么、到第几步；失败给原因和重试入口 |
| **存了就要报** | 存进去却不在 `--json` 里报出来，Agent 查到的空看起来正好像「没问题」 |
| **同一件事只有一处说了算** | 两处各算各的，迟早不一样。这个项目在这上面栽过不止三次 |
